# Portfolio Watch Skill — 项目约定

PM 作业：构建一个 Skill，让任意用户从一句话（如「盯下我的 NVDA、TSLA、AAPL，有大事提醒我」）
生成带界面和告警的 Portfolio Watch Playbook。**核心要求是复用性**——对没见过的组合也要能用。

作业明确交给 Skill 决定的三件事：**什么算异动 · 什么是噪音 · 多信号并发怎么排序**。
三件全是告警问题，界面只是它的显示面。

## 一、结构契约 ⚠️ 已锁定，不要再改

### 信号只有两层，「族」不是一层

```
M 层 · 指标    基础量，每个定义一次        M1 z_rob · M3 RVOL · M7 内部人簇计数
     ↑ 被引用（多对多）
S 层 · 信号    触发规则，引用 M 的 ID       PV1 = |M2| ≥ θz AND M3 ≥ θv
```

**族（PV/EV/DR/MA/PO/PF/US）只是 ID 前缀，不是层级。**
不要再提「信号类别 → 信号 → 指标」三层结构——指标被多个信号复用（M3 同时被 PV1/PV2/PO2 用），
嵌套必然导致重复定义和不一致。这个问题已反复讨论过，结论就是两层。

### 信号只在一处定义

```
product/signal-spec.md  ⭐ 已定案信号的唯一定义处。改阈值/算式/适用范围 → 改这里
backtest/signal-registry.md   实验记录：测过什么、结论是什么、被证伪的为什么
其他所有文档             只引用 ID，不重复定义

⚠️ **两份文件不重复定义任何一条信号。** 已定案的定义在 spec，其余在实验记录。
进 spec 的门槛是「状态不会再变」，不是拿到某个证据符号 ——
展示类 · 日历类 · 用户设定值本来就不取证据等级。
```

**发现任何文档里出现了阈值数字或触发式，先检查是不是该改成引用 spec 或实验记录。**

**ID 命名在所有产物中一致**，包括 `mock/` 里的 HTML 标签、图例、列表文案。
用 `PV1–5 · EV1–6 · DR1–4 · MA1–3 · PO1–4 · PF1–3 · US1–3`（28 条），
不要出现 `P1`、`变体 C`、`R2` 这类历史别名（回测对照组名只能出现在「对照关系」的说明里）。

**mock/ 是探索工具，不是配置载体。** 它可以只实现部分规则（如不实现高波降级），
但必须在页面上写明差异，否则会被当成规格来源。

### 证据等级只能由审核授予 ⚠️

```
自测跑完  →  🟡 待审核        自测最多标 🟡
审核通过  →  🟢               只有独立审核能给 🟢
审核否定  →  🔴 或退回 🟡
```

**Phase 1 初版直接从「跑完」跳到 🟢，结果三条里两条被审核撤回。**
「跑完」不等于「结束」。改动信号定义后，必须回头确认回测测的还是同一条规则。

### 每条信号的标准结构

```
触发 · 参数 · 属性          给实现者
含义与用法 · 文案模板        给用户    ← 不能省，对应告警富化要求
血统与证据                  给评审
```

**每条信号有「类型」属性**：`告警`（进告警流）· `修饰符`（另一条信号的字段）· `展示`（只在界面，永不推送）。
**类型可以因回测结论改变，编号永不改变** —— 否则历史文档里的引用会失效。

**新增或修改信号时六块都要有。** 目前只有 PV 族补齐，其余 20 条缺后两块（registry §八 缺口）。

### 两个标注维度，别混用

```
血统   这想法哪来的     🏛 平台 · 📚 业界 · ✍️ 原创
证据   凭什么说数对     🟢 已验证      测了，通过判据
                    🟠 已测未达判据  测了，没通过，但证据不足以证伪（样本不足 · 规则不可复用）
                    🔴 已证伪      测了，有明确的零效应或反向证据
                    🔵 引用未自测   别人的结论，我们没在本组合上验过
                    🟡 待验证      还没测
                    ⚪ 无法验证     数据或方法阻断，不是没开工
                    —  不适用      不提出统计主张（展示类 · 用户设定值）

⚠️ 🟠 与 🟡 的区别是「做没做过」，🟠 与 🔴 的区别是「有没有反证」。
   三者曾全部挤在 🟡 里，导致「N 条待验证」既指没做也指做了判不了。
```

⚠️ **这是计费记载第六次出错。** 前四次是「取数 0 credits」「market-news 0 credits」
「price-target-news 免费」「内部人端点免费」，**根因都是即时读余额、没等计费延迟**。

⚠️ **第六次的根因又不同：漏了一整个计费来源。**
`source` 列里有 `playbook` 一项 —— 脚本跑起来本身按时长收费，与拉什么、调不调 LLM 都无关。
我一直按「端点 × 单价」的模型核账，那个模型里根本没有「运行」这一维，
所以它不是算错了，是**压根没进入视野**。

```
❌ 核账模型   成本 = Σ(端点调用 × 单价)
✅ 核账模型   成本 = Σ(端点调用 × 单价) + Σ(运行时长 × 2/分钟) + Σ(LLM rollup + 检索子条)
```

**核账前先把 `source` 的取值枚举一遍**，再决定每一类怎么算 ——
而不是拿着已知的几类去账单里找它们。前者会撞见没见过的，后者永远撞不见。

⚠️ **第五次的根因不同：一次逻辑调用在账单里是 5–8 条，大小相差两个数量级。**
带检索的 `ask()` 产出一条 79–279 的 rollup，外加若干条 1（serper）/ 5（brave）的检索条目。
拿条目数去除总额得到「均价 94」——**那个数不对应任何真实的东西**：
19 条 1 credit 的检索把均价稀释了。

```
❌ 错法   总额 ÷ 条目数
✅ 对法   按 createdAtMs 排序，认出 rollup 条目，数 rollup 的个数
```

**凡是一次操作会产出多条账单的，均价必须按「逻辑调用」算，不按「账单条数」算。**
这与第六类同形：核对的量与以为在核对的量不是一个。
可靠做法只有一个 —— 跑完等几分钟，然后解析 `alva credits items --today` 里每条的
`extras.by_endpoint`，按端点核对调用数：

```bash
alva credits items --today | python3 -c "
import sys,json,collections
d=json.load(sys.stdin); by=collections.Counter()
for e in d['items']['edges']:
    ex=json.loads(e['node'].get('extras') or '{}')
    for k,v in (ex.get('by_endpoint') or {}).items(): by[k]+=v.get('calls',0)
    if e['node'].get('source')=='ask': by['[ask]']+=1
[print(f'{k:52s} {v}') for k,v in by.most_common()]"
```

而本 session 未调用过 LLM —— 唯一来源是 PF3 验证里的 `get_company_themes` 等 MCP 调用。
**该验证报告里「`search_contracts` 与 `get_company_themes` 免费」的结论应据此撤回**，

⚠️ **`alva run` 返回的 `credits_used` 字段不可信** —— 实测恒为 0，即使该次运行确实产生了计费。

### 第六类：核对的量与以为在核对的量不是一个 ⚠️ 2026-08-21 追加

前五类讲「结论下早了」和「没同步到位」。**第六类讲「检查本身是假的」** ——
检查跑了、通过了，而它根本没在查你以为它在查的东西。

| 事故 | 形状 |
|---|---|
| 数字白名单把 `7.35` 报成越界 | 输入是 `-7.35`，白名单存带号串，比之前没规范化 |
| 断言按下标配对两个**各自排序**的列表 | 表是 平时→价格→量能，卡是 价格→量能→平时。措辞全对却报三条不匹配 |
| 同一个错一周内犯第二次（区间轴三点） | 文档顺序是 [低,**现价**,高]，我以为是 [低,高,现价] |
| 取数汇总把 `ERR 400` 数成「1 根」 | 错误就在返回里，被自己的计数掩盖成成功 |
| 内部人 mock 名字无放回抽 | 人数恒等于笔数 → 「两个数都要印」那条断言**永远不会失败** |
| 破坏性测试 patch 了 `T` / 模块作用域 `const` | 渲染和断言同时被改，两边一致所以不报错 |

```
1  需要手工把两个列表对齐时，那个对齐动作本身就是 bug
   → 两边打同一个键（data-rd / .rng-lo），按键配对，不按下标
2  比较前先规范化      去符号 · 去千分位 · 去尾随零 · 剥单位
3  破坏性测试必须只改「被测的那一侧」
   同时改了渲染与断言，等于什么都没测
4  一个不可能失败的断言等于没有断言
   造反例让它真的失败过一次，再相信它
5  汇总/计数不得把失败态折叠进正常态
   "ERR 400" 不是「1 根」
6  跨层传递不要写字段白名单
   `map(h => ({i:h.i, d:h.d, z:h.z}))` 会静默丢掉此后新增的每一个字段，
   而且丢法是「值变成 undefined」→ 渲染成破折号 → **看起来像上游没给**。
   症状指向错误的一方。用展开（`{...h}`）而不是枚举
7  验收标准本身要先做破坏性测试
   「切换前后表宽必须相等」——表被约束在固定宽度里，某列缩了富余分给后面的列，
   总宽恒相等。**这个验收标准永远不会失败**
8  破坏性测试的强度必须大于阈值
   翻转一个属性只挪动 0.7px、而断言阈值是 1px → 断言静默。
   「没响」既可能是对的，也可能是测得太轻，两种情况长得一模一样
```

### 第七类：结构选错了，于是信息被结构吃掉 ⚠️ 2026-08-22 追加

前六类讲的是「结论错了」「没同步」「检查是假的」。**第七类讲「代码结构本身在丢信息」** ——
每一行单看都对，合起来少说了一件事。

| 事故 | 形状 |
|---|---|
| `if(r && r.length) out[k]=r` | 早返回 `[]` 与「跑完没发现」在报告里同一行 |
| 「ran」只数 pass | 一条到处失败的检查被报成「从未到达」——**恰好与事实相反** |
| `n<60 ? A : m23不足 ? B : C` | **两道门都不过的标的只说第一句**，读者不知道第二项也没测 |
| `map(h => ({i:h.i, d:h.d}))` | 字段白名单静默丢掉此后新增的每一个字段 |
| 阈值蕴含 | θz=10 时量能腿恒真，AND 只剩一条腿在起作用 |

```
共同点   信息在「表达它的结构」里被丢掉，不是在「算它的代码」里算错
识别法   问「这个结构能不能表达出全部可能的状态」——
        三种结局挤进布尔、并列关系写成阶梯、执行统计排除失败态，都是不能
```

⚠️ **`finally` 保证的是「这个调用结束时恢复」，不是「期间没人看见」。**
单线程里两者只在有 `await` 的时候才分开 —— 并发读期间临时改共享状态，
`finally` 让它看起来是安全的。

### 第八类：断言的主语变了，而断言还在 ⚠️ 2026-08-22 追加

第六类是「检查从一开始就没在查你以为的东西」。**第八类是「它曾经查对了，
后来被测对象变了，于是它悄悄变成了无意义」** —— 而失效的那一刻没有任何信号。

```
auditFilingAxis   按「只画买入 · 一天一个标记 · 固定 30 天窗口」写
                  三条前提后来一条都不成立
                  它断言的东西不是被违反了，是变成了无意义，而报告里照样算「跑过」
```

**它比「不可能失败的断言」更隐蔽**：那种从一开始就是死的，
这种有过真实的保护期，所以没人怀疑它。

```
识别法   改了被测对象的形状之后，回去看它的检查还在断言什么 ——
        问「这条断言现在指的是哪个东西」，而不是「它还过不过」
硬规则   改数据形状或渲染结构时，同一次改动里必须重读它的检查，
        并让它对新形状失败一次
```

⚠️ **「跑过」不等于「查了」。** 执行统计要能区分
「跑完没发现」「早返回」「断言的对象已不存在」三种 —— 挤进一个「pass」就等于放弃这一类。

### 第九类：这一轮的产物里，有还没发生的事 ⚠️ 2026-08-22 追加

第七类讲结构吃掉信息，第八类讲断言的主语变了。**第九类讲「时钟本身是错的」** ——

| 事故 | 形状 |
|---|---|
| 加密盘中 bar 延到取数时刻，asOf 钉在 16:00 ET | 「16:05 跑的那一轮」里出现 17:30 的告警 |

```
共同点   一个来自「有收盘的市场」的默认值（16:00 ET）被套到 24 小时市场上
识别法   把每一个落盘的时刻和「产出它的那一轮」比一次。
        任何 finding 都不能晚于 generatedAt —— 一行断言，不需要任何统计
```

### 呈现风格

用户是 PM，要**结论先行 + 有数字支撑 + 主动标注不确定性**。
表格和对比优于长段落。**推翻自己前面的结论时直接说，不要绕**；
但也不要反复重构已经定下来的结构——见第一章。

**两条硬性写作约定**（文档与对话都适用）：

1. **一律陈述语气。** 不用「为什么 X」式的设问标题、加粗引导句、表格列头。
   标题直接给结论（`价格阈值无需分档`，不是 `为什么价格阈值不用分档`），解释放正文。
2. **不裸用字母代号。** 优先用中文全称做表头（`触发频率 次/年` 而非 `F/年`）。
   确需代号时，**在该表格正下方紧跟一行 `<sub>` 备注**说明每个代号的含义。
   跨文档的单一定义解决「不重复定义」，解决不了「就地可读」——读结果文档的人不会先翻定义文档。

> 例外：`backtest/plan.md` §一 是四个验证量的定义处，公式里保留 $F$/$V$/$A$/$P$ 符号，
> 但**标题一律用中文全称**（`### 触发频率 · 描述量`），不再用「代号 · 全称」并列。
> 信号 ID（PV1/EV2/M3…）是有 registry 背书的正式标识，不属于「随意代号」。
