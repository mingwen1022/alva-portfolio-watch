## 〇、三条贯穿全页的规则

### 时间戳一律来自 `meta.freshness`，页面上不得硬编码

```
❌  ovClose: 'close 16:00 ET'        写死的文案键，14:30 的时候也照样写「收盘」
✅  盘中   截至 14:30 ET             收盘后   收盘 16:00 ET
```

**逐块标自己的时刻，不设统一的 last updated。** `meta.freshness` 里是三个独立时刻，
节奏差很远（价格 15 分钟 · 新闻按需 · 财报日历每日 07:00），
统一一个必然对其中两个说谎 —— 与 Tab 3 的「时间戳逐块标」同一条规矩。

### 数据陈旧必须看得出来

```
正常   行情更新于 14:30
异常   行情更新于 14:05 · 已超过一个刷新周期
```

判据 `now − freshness.prices > 刷新周期 × 1.5`。

⚠️ **静默日的可信度整个挂在这上面** ——
用户凭什么相信「今天没有异动」是真的没异动，而不是我们没跑。

### 校验清单要从数据里读，不要照着文案抄

禁词表、拉丁词白名单、列集合这类审计清单，**凡是能从结构或数据里取的就去取**。
手写副本在数据一变的那一刻就过期：实测手写拉丁词白名单在切换持仓本时
立刻报出 MSFT · AVGO · JNJ · ABBV · MRK · TMO · AMZN · WMT 一片假阳性。

**只有「产品刻意保留」的那部分才写死**，因为那是决定不是数据。

## 一、页面结构

### 四个 Tab，按「这是什么」分，不按投递层级分

| Tab | 内容 | 判断标准 |
|---|---|---|
| **1 · 持仓与告警** | 告警 + 今日扫描 + 资产总览 + Allocation（三切面）+ 净值图 + 持仓表 + 新闻/财报日历 | 我们验过，敢让它占首屏 |
| **2 · 标的详情与告警历史** | 切换单只持仓，看它的全部相关信息 | 客观事实，逐标的组织 |
| **3 · 市场** | 指数 · 波动率 · 利率 · 商品 · 加密 · 日历 | **客观数据，不是信号源** |
| **4 · 方法** | 什么算异动 · 什么是噪音 · 怎么排序 · 能力边界 | 作业问的三件事的答案 |

### 投递层级不是页面结构

registry §6.1 的 L1–L4 回答的是「投到哪个接触点」：
L1 是渠道（打断用户），L2/L3/L4 都是「打开 app 就在那儿」。
**把四层直接映射成四个 Tab 是错的** —— 那把「渠道」和「位置」并列成了一个维度。

L1 推送与 Tab 1 顶部是**同一批信号的两个出口**：
能推送的一定在首屏，首屏的不一定推送。

## 二、无 portfolio 连接时的降级

| | 有 portfolio | 只报 ticker |
|---|---|---|
| 持仓权重 | `alva portfolio` 真实权重 | **等权假设**，界面明说 |
| 盈亏 / 成本 | ✅ | ❌ 告警卡片上下文块 ④ 整块不显示 |
| PV1 · PV5 · EV4 · EV6 | ✅ 不受影响 | ✅ 不受影响 |
| PF2 · PF3 | ✅ | ⚠️ 等权下退化，标注「按等权估算」 |
| US1 / US2 / US3 | 需用户设线 | 同样需要 |

**核心告警一条都不依赖 portfolio。** 只有组合层和盈亏受影响。

⚠️ **等权假设必须在界面明说**，避免用户以为那是他的真实仓位。

## 三、数据刷新与自动化

平台链路：`alva deploy create`（cronjob）→ `alva release feed` → `alva alert`（推送）。
**最小间隔 1 分钟**，`--args` 可传参，`deploy runs` / `run-logs` 可查执行历史。

| 信号 | 建议频率 | cron |
|---|---|---|
| PV5 | 盘中每 15 分钟 | `*/15 9-16 * * 1-5` |
| PV1 | 收盘后一次 | `5 16 * * 1-5` |
| EV1 内部人簇买 | 每天一次（申报数据日频） | `0 8 * * *` |
| EV4 财报日历 | 每天一次 | `0 7 * * *` |
| DR1 资金费率 | 跟 8 小时结算对齐 | `5 0,8,16 * * *` |
| PF2 / PF3 主题 | 持仓变化时 + 每天一次 | `0 9 * * *` |
| Tab 3 市场数据 | 每小时 | `0 * * * *` |

**每个 cronjob 独立计费、独立失败** —— 低价值的信号可以调低频率省成本。

⚠️ 加密 24/7，PV5·加密 的 cron 不能只覆盖美股交易时段。

## 四、Tab 1 · 持仓与告警

### 版面自上而下

```
① 告警区        有告警时置顶；无告警时收成一行「今日无异动」
② 资产总览      总资产 · 当日盈亏 · 距高点回撤 · 持仓分布
③ 持仓列表      每只：价格 · 盈亏 · 展示类标注
④ Allocation    三个切面：按标的 · 按资产类别 · 按主题（PF2 / PF3 并入此处）
⑤（本期不做）    盘后日报已移出，见 future/postclose-digest.md
⑥ 今日相关新闻   底部常驻
```

**告警区在最上面而不是在总览下面。** 这个产品的承诺是「有大事提醒我」，
把资产数字放在告警之前等于让用户每次都先滚过一屏才看到他订阅的东西。
无告警的日子它只占一行。

### ① 告警区

| 信号 | 标的 | 时点 | 证据 |
|---|---|---|---|
| **PV1** 双确认 · 日线 | 美股 · 加密 | 收盘后 | 🟢 独立审核通过 |
| **PV5** 双确认 · 盘中 15 分钟 | 美股 · 加密 | 实时 | 🟢 独立审核通过 |
| **EV4** 财报日历 | 仅美股 | 提前 1 日 | — 日历类 |
| **US1 / US2 / US3** | 美股 · 加密 | 实时 | — 用户自设 |

**系统凭自己的判断打断用户的只有 PV1 · PV5 · EV4。** 另三条是用户自己划的线。

#### 三条必须遵守的文案约束

```
① 不写「双确认」   盘中的 θv 是严格度旋钮不是第二个确认
                 等触发数下增益 美股 +0.006（p=0.835）· 加密 −0.128（p=0.860）
                 写「价格异常，且已过滤低量噪音」
② 不写「哪些标的更可靠」  逐标的秩不跨期存活，有效 n ≈ 1 次市场状态抽样
③ 不按固定条数做容量规划  告警量年际摆动 1.5 倍（5.79% → 3.78%）
```

⚠️ **PV5 开盘第一根 bar 的量能腿几乎不起作用**：`P(量能腿 | 价格腿)` 开盘 88.6%、
尾盘 33–50%、全局 54.2%，而开盘那根贡献 11.2% 的触发。那一根的告警本质是单腿的。

#### 投递上限要在标的页上说，不能只在被压下来的那张卡里说

**它是这只票的常驻属性,不是某一次告警的属性。**

```
Tab 1 持仓表   代码后面一枚「不推手机」标记,与兜底阈值标记同一位置同一字形
Tab 2 覆盖块   一句话说清:留在页面上 · 全历史多少根 · 倍数与区间下界
告警卡         真的被压下来那次,卡顶「为什么没响你的手机」
```

⚠️ **原来只有第三处。** 于是一只从没触发过的标的,用户永远不会知道它的告警不会响手机 ——
而标的页当时还写着「价量规则适用于这只标的」,读起来就是「它会推我」。
**规则确实适用,只是结论到不了你手机,这两句话必须一起出现。**

⚠️ **两种「不管用」措辞不同,不能合并:**

```
测过了没测出来   全历史 N 根,触发后五天与平常五天分不开 —— 倍数 X,区间下界 ≤ 1.0
还没测够        N 根记录凑不出判断所需的五个独立触发段
```

前者以后也不会变好,后者攒够样本就可能翻。合成一句,用户没法判断该不该等。

#### 折叠卡的两行

```
第一行   图标 · 代码 · [资产类别]          ······   价格   涨跌幅
第二行   [信号 pill] [×N]                  ······   日期 + 时刻
```

**资产类别跟着代码走，不跟着信号走。** 它是关于标的的事实，
排在信号名后面时读者要先分辨那是不是第二条规则。

⚠️ **只有窄卡这么放。** 宽卡的标识行是固定列宽网格，这个标签在那一行上吃掉 82px，
而那一行右边正是四个读数要挤进去的地方。同一个标签两种放法，是因为两种卡的约束不同。

⚠️ **资产类别标签不用灰色。** 卡上已有四种颜色在承担意义 ——
绿/红是方向、深青是信号本身、琥珀是警示 —— 灰是「次要」，
读者会把它读成「这条不太重要」。它不是次要，只是**另一类**事实。

⚠️ **日期一律印，不做「与今天不同才印」。**
22 号打开页面时,日线卡讲的是 21 号收盘那件事、盘中卡讲的是 22 号 ——
两张卡并排,而「没有日期」这个信号只有已经知道规则的人才读得出来。
落款放第二行最右：它是这张卡的落款，不是标题的一部分。

#### 告警卡片的上下文四块

纯告警（「NVDA 触发双确认」）确实太弱，但补强它的正确方式**不是猜原因**，
而是把用户下一步一定会问的四个问题就地答掉。四块里三块是纯事实、零统计主张，
不需要任何验证；只有第二块涉及外部材料。

| 块 | 界面顺序 | 回答的问题 | 覆盖率 | 怎么产生 |
|---|---|---|---|---|
| **⓪ 触发了什么** | **1** | 「**凭什么给我推这条**」 | 100% | 规则本身 |
| ① 是大盘还是它自己 | 4 | 「今天所有票都在跌吗」 | 100% | 算术 —— 并列两个涨跌幅 |
| ② 归因 | 3 | 「为什么会动」 | 时点四档恒有输出 | **Alva Ask**，见 §5.7 |
| ③ 这个幅度算大吗 | 5 | 「以前也这样吗」 | 100% | 算术 —— 历史分位是描述 |
| ④ 我亏了多少 | 6 | 「对我影响多大」 | 100% | 算术 |

<sub>价量图排 2，紧跟 ⓪ —— 它画的是 ⓪ 里那两条线和读数在时间上长什么样。</sub>

#### 每种告警的弹窗各有各的构成 —— 不是一份通用版面

**上表是全集，不是每张卡都长这样。** 不同信号回答的问题不同，
硬套一份通用版面的后果是：每次改一处都要顾及全部类型。
**下表是唯一的事实来源 —— 资产类别的差异写在格子里，不写在表外。**

| 块 | PV1 日线 | PV5 盘中 | US1/2/3 用户线 | EV4 财报日历 | DR1 费率极端 |
|---|---|---|---|---|---|
| **⓪ 触发了什么** | 价格腿 + 量能腿 + 日常波动 + 偏离倍数<br>美股量能线 2.0×<br>加密 3.0× | 同左，按 15 分钟口径<br>美股 θz 4.75<br>加密 θz 10.0 | 你设的线 + 现在到哪了<br>止盈/止损是绝对价<br>回撤是距自身高点的百分比 | 日期 + 盘前/盘后 | 当前费率 + 阈值 |
| **价量图** | 日线 60 根 | 15 分钟，最近 3 个交易日<br>美股只画 RTH<br>加密画全天 | 日线 60 根 + 把用户线画上去 | **不画**<br>没有「移动」可画 | **画费率序列**，不画价量 |
| **① 大盘对比** | 美股：SPY 并排<br>**加密：不显示**（无市场基准） | 同左 | 同左 | **不显示** | **不显示**（仅加密） |
| **② 归因** | 调 | 调 | **不调**<br>见下 | **不调**<br>日历自带原因 | **不显示**（仅加密） |
| **③ 幅度分位** | 502 根日线里第 N 大<br>美股与加密都显示 | **同一时刻的 90 根**里第 N 大<br>美股 26 个时刻<br>加密 96 个时刻 | **不显示**<br>用户线是绝对值，与该票的历史分布无关 | **不显示** | **不显示**<br>费率不是价格移动 |
| **④ 我亏了多少** | 显示 | 显示 | 显示 | 显示 | 显示 |

⚠️ **「不显示」是整块不渲染，不是留一个空块写「不适用」。**
与资产类别裁剪同一条规矩 —— 不适用不占版面。

⚠️ **图只画这条规则读的量。**

```
PV1 / PV5   读价格 + 成交量   →  两个面板都画
                              →  触发那根在【两个面板】都标出来
US1/2/3     只读价格          →  只画价格面板，不画成交量面板
EV4         不读价量          →  不画图
```

**画一个这条规则根本不读的面板,等于请读者去找一个不存在的信号。**
用户看回撤线的卡时会去成交量面板里找标记 —— 而回撤线跟成交量无关。

⚠️ **PV 卡的触发标记必须同时出现在价格与成交量两个面板上。**
告警历史图已经这么做（琥珀柱），弹窗要一致 ——
**两条腿是这条规则的全部内容，只标一条等于只说了一半。**

⚠️ **千位以上的坐标轴要用单位。** `80000000.00` 读不出量级，写 `80M`；
加密的成交量更大，`1956029005.00` 写 `1.96B`。**小数位同时收掉** ——
成交量不需要两位小数。

⚠️ **③ 在 PV5 上换的是分母不是取消。** 15 分钟的移动不是日线移动的缩小版，
放在同一条日线分布轴上就是把两个量当成一个。**同一时刻**才是它的可比总体。

⚠️ **加密不显示 ①，但显示 ② 与 ③。**
① 需要一个市场基准，加密没有；
② 的严链（EV6）确实仅美股，但**「材料为空时让模型自己检索」那条路不受资产类别限制** ——
加密照常有归因，只是材料来自模型自搜而不是严链；
③ 是这只票自己的历史分布，纯算术。

⚠️ **用户线不做归因。** 它的卡不主张「这次移动不寻常」，只说「你划的那条线被碰到了」——
**归因回答的是「为什么动」，那是价量卡的问题。**
在用户线卡上放一段解释，等于替用户自己设的规则找理由。

⚠️ **不做归因意味着连时点徽章都不出,不是出一个「没有找到报道」。**
`timing = none` 有两种来源：**调了没材料**，可以显示；**压根没调**，整块不渲染。
「没有找到报道」是在说「我们查过了」。

### 告警流分两组：今天新增 · 持续中

```
今天新增   novelty > 0   事件型每次都在这一组；状态型只有转折那天在
持续中     novelty = 0   状态型持续成立的日子。单独一组，不推送
```

**「持续中」那一组必须写出它从哪天起成立**（`state.json` 的 `since`）。
实测一条回撤线连续成立九个半月 —— 不写起始日，读者以为是今天刚发生的。

⚠️ **「持续中」默认折叠，但组标题必须始终可见，且带三个事实：**

```
持续中 · 3 条 · 最早自 2025-11-03        ← 永远显示，不随折叠消失
  ▸ 展开后才是三张卡
```

**折叠的是卡片，不是事实。** 组标题在那里说「有三条线你还踩着，最早的踩了九个多月」——
这句话本身就够用户判断要不要展开。

#### 告警区不吸顶，跟着页面一起滚

告警区占住右侧那一列，**但它是普通的内容块，不是 sticky**。

⚠️ **吸顶会造成「滚动牢笼」**：告警区一旦高过一屏，读者必须先把左侧滚到底，
右侧才继续滚。**两列各有各的滚动进度，而滚轮只有一个** ——
指针在哪决定滚哪一列，这件事读者事先不知道。

⚠️ **也不要给它内部滚动条。** 那是同一个问题的另一种形状：
一个页面上的第二个滚动条，行为取决于指针位置。

**它无界的问题由折叠解决，不由容器解决**：超过十条折叠 · 「持续中」折叠。
两处都折叠之后，告警区的高度就有界了，不需要任何滚动容器。

#### 「过线了但手机没响」这段说明读 `delivery`

```
delivery.level      这条实际到达的投递层
delivery.cappedBy   被谁压下来的 —— 这一句的唯一数据来源
```

**界面不得自己 join 三处上限再取 min。** 那句话要说的是结果加原因，
而不是三个上限值。`cappedBy = "symbol_grade"` 对应的措辞是
「两条线都过了，但这只标的自己的历史还不支持把它推到手机上」。

⚠️ **不要写成「效应无效」。** `effect_unclear` 与 `insufficient_sample`
说的都是「还判不出来」，不是「判出来没有」。

⚠️ **不要整块不渲染。** 这一段正是产品可信度的落点 ——
两条腿都过、扫描表有触发标记、而手机没动静，不加说明就是系统坏了。

⚠️ **不能整组消失，也不能进历史。** 条件确实还成立，用户划的线还被踩着。
藏起来就是把「还在跌」说成「没事了」。

⚠️ **必须折叠的理由是它无界。** 状态型信号数 = 用户线数 + DR1 + PF2，
30 只标的每只三条线就是 90 条 —— **不折叠，告警流会被永远成立的东西撑开，
而「今天新增」那几条被挤到屏幕外**。今天恰好只有 3 条不代表明天也是。

⚠️ **也不要让它每天占据流顶部。** 那正是它 `novelty = 0` 的原因。

### 单标的盯盘与组合盯盘是同一套界面，减块不减层

用户说「盯一下 NVDA」和「盯我的 NVDA、TSLA、AAPL」进的是同一个 Playbook，
**区别只在哪些块有意义**，不是两套界面。

| 块 | 组合 ≥ 2 只 | 单标的 |
|---|---|---|
| 告警流 | 有 | 有 —— 这是两种模式共同的核心 |
| 扫描表 | 逐只一行 | **一行。仍然要有** —— 它是「引擎跑过了」的唯一证据 |
| 持仓 KPI · 总额 · 盈亏 | 有 | 有仓位则有，无仓位则整块缺省 |
| 配置切面（按持仓 / 类别 / 主题） | 有 | **整块不出** —— 一只标的的「配置」是 100%，是废话 |
| PF2 主题集中度 · PF3 主题共振 | 有 | **不适用** —— 需要 ≥ 2 只才有集中度可言 |
| 净值曲线 | 有 | 有仓位则是这只票的持仓市值曲线，无仓位则退化成价格曲线 |
| Tab 2 逐标的页 | 可切换 | **就是它自己，去掉切换器** |
| Tab 3 市场 · Tab 4 方法 | 有 | 有，不变 |

⚠️ **无仓位也要能用。** 用户可能只是想盯一只没买的票。
`portfolio.json` 的 `linked: false` 已经定义了这种形态 —— 单标的复用它，
不要另发明一个「watch-only」模式。

⚠️ **单标的下那句「N 只超出自身常态范围」要换措辞，不是把 N 填成 1。**
「1 只超出自身常态范围」读起来像统计口径，而用户只盯了一只 ——
应当直接说这只票今天怎么样。

⚠️ **不要因为只有一只就省掉扫描表。** 零告警那天，
一行「NVDA 今天两条线都没过」是页面上唯一由信号产生的内容。
**省掉它，用户看到的是一个空页面。**

⚠️ **EV4 与 DR1 不要往价量卡的版面里塞。** 前者没有「移动」，
后者的量是费率不是价量 —— 硬套会长出一排空块。

⚠️ **实现上共用骨架，按类型开关块。** 五份独立实现意味着 ⓪ 的排版规则、
④ 的持仓格式要维护五遍。**改一格只动一格，但那一格的代码只写一次。**

##### ① 是大盘还是它自己

```
NVDA  −6.2%        SPY  −0.3%
```

**并列展示，不做减法也不给 z 分数。** 用户看两个数字就能判断，
而「残差 z = 2.4」需要我们背书一个统计模型 —— 那个模型（当日残差 z）
目前 p = 0.042、不过多重比较，**没有资格出现在界面上**。

⚠️ **加密整块不显示。** 我们的能力边界写着「加密无市场基准」——
BTC 占全加密市值一半以上，市场模型分解对它失效；而加密总市值端点只给单币市值，
分母根本拿不到。

**不要退而用 BTC 当基准。** 「SOL +6.9% / BTC +7.3%」看起来是两个数并排的算术，
实际藏着一个建模主张：**BTC 代表加密大盘**。那个主张我们没验证过 ——
BTC 自己有 ETF、有减半、有它自己的特异风险，它动而 SOL 不动的时候，
这个对比给出的是反的结论。

**卡片上其余每一块要么是算术、要么明确标了不确定。** 一个看起来像算术、
实际是未验证模型的块，比不放更糟。加密的告警卡少这一块，并在 Tab 4 说明为什么。

##### ② 当日同期发生了什么

**措辞固定为「当日同期」，不写「原因」。** 依据：判别力 79% 在日级、21% 在 bar 级，
截断口径下 bar 级成分只在 11:30 ET 前触发的那批上成立。

**筛选链**

```
① 相关度      该标的的 relevance_score = 1.0
② 事件类主题   topics 含 earnings / M&A / IPO 且该主题相关度 ≥ 0.5
③ 时点        |publish_time − alert_time| ≤ 120 分钟，且 publish_time ≤ alert_time
④ 排序        按发布时间倒序，取最近 3 条
```

⚠️ **先筛后排，不能先排后筛。** 新闻密度逐标的差 **500 倍**
（JPM 200 条/天 · NVDA 172 · XOM 15 · MSTR 1.2 · QFIN 0.02）——
对 JPM 取「最近 3 条」拿到的是最近二十分钟的转载，对 QFIN 可能跨越半年。

**四档文案**

| 档 | 条件 | 文案 | 占比 |
|---|---|---|---|
| 静默 | 无符合材料 | 只显示告警本身，**不写「未找到原因」** | 81% |
| 当日同期 | 筛选链命中 · PV1 日线 或 PV5 · 11:30 ET **前** | 「当日同期发生了：〈标题〉」 | 19% |
| 当日稍早 | 筛选链命中 · PV5 · 11:30 ET **后** | 「当日稍早：〈标题〉」**不与该 bar 关联** | — |
| 财报日 | 真实财报日历命中 | 「今天是〈公司〉财报日」 | 按日历 |

**不设「原因是」这一档。** 大幅异动并不更容易归因
（稳健 z 分四档 45.9% / 41.0% / 40.0% / 50.0%，无单调关系）。

#### 材料四档决定材料从哪来，时点四档决定怎么标

上表四档回答「筛选链有没有拿到材料」。**它不决定调不调模型** ——
价量卡一律调，材料为空时让模型自己检索。决定不调的只有信号类型：

| | 调模型 | 归因块 |
|---|---|---|
| 用户线 US1–3 · EV4 | **不调** | **整块不渲染**，连徽章也不出 |
| 价量卡 · 筛选链有材料 | 调，材料随上下文传入 | 按来源时刻算 |
| 价量卡 · 筛选链为空 | 调，让它自己检索 | 自搜到 → `untimed`；仍为空 → `none` |

⚠️ **「材料为空就不调」是错的，那正是自搜唯一有用的场景。** 筛选链只覆盖美股，
按这条写法**加密永远没有归因**。实测 5 条加密告警全部返回了 3–4 条真实来源。

⚠️ **不调 与 调了但没找到 是两回事，渲染必须不同。**
前者整块不出；后者要说出「今天没有找到相关报道」——
一个不说话的空块会被读成系统坏了（原则六）。

时点四档，全部由代码按时间戳算，**不由模型判**：

```
before    有筛选链来源，且存在早于移动时刻的     「移动前 80 分钟有这些报道」
after     有筛选链来源，全都晚于移动时刻         「移动之后有这些报道」
untimed   只有模型自搜到的来源                 「找到了报道 · 时点未核实」
none      一条来源都没有                      「今天没有找到相关报道」
```

⚠️ **`after` 不是失败档。** 事后报道对用户有用，只要标清楚是事后的。
渲染上它拿与 `before` 同样的字号与来源列表，要区别的是它与 `none`。

⚠️ **`untimed` 不能并进 `none`。** 并进去之后**徽章会在几条来源之上说
「没有找到报道」** —— 眼睛看得见找到了。它用实心徽章，不用描边：
描边是 `none` 的样子，「有材料」不该长成「什么都没有」。

字段见 [output-schema §三](output-schema.md) `attribution`；
链路见 [data-pipeline §零](data-pipeline.md)。

#### 静默档的措辞

**可以写「没找到」，但必须同句给出它是常态。** 81% 的告警日没有材料，
单独一句「未找到」会被读成系统故障。

```
✅  没有找到能解释这次移动的公开信息。81% 的告警日都是这样。
❌  未找到原因                        单独出现时读作故障
❌  没有找到 ⋯⋯，这不是扫描有缺口       用「不是什么」说明，违反写作约定
```

**沉默本身有歧义**：界面上「0 条材料」与「有材料但没显示」长得一样，用户无从分辨。
给出结论并同句说明它常见，两个顾虑都解决。

⚠️ **加密的严链取不到材料**（六个相关度阈值 × 两个窗口 × 媒体家数门槛，倍数全部 < 1.0）。
**这不等于加密不做归因** —— 材料为空时模型自己检索，来源打 `origin: "model"`、
时点档位落在 `untimed`。加密的告警卡片是 **②③④**，缺的是 ①（加密无市场基准）。

**情感着色**（三处用到新闻的地方共用：本块 · ⑤ 今日相关新闻 · Tab 2 相关新闻）

```
|情感| ≥ 0.35 着色（占 41.9%），其余灰色
阈值取 0.35 而非 0：低于它的占 58%，全部着色会让整页都是绿点，颜色不携带信息
⚠️ 红点比绿点信息量大 —— 财经新闻天然偏正 3 : 1，不要用等宽的红绿对称配色
```

| 任务 | 做不做 | 依据 |
|---|---|---|
| 标注**这条新闻**正面/负面 | ✅ | 稿件属性，不是对市场的主张 |
| 用情感推断**当天涨跌方向** | ❌ | 净命中只有 31% |

##### ③ 这个幅度算大吗

```
今日 −6.2%，是这只票近两年第 4 大的单日跌幅
```

历史分位是描述性事实。⚠️ 受 PV4 覆盖标注约束 —— 基线不足 60 日的标的
这一行显示「历史数据不足」而不是一个失真的分位。

##### ④ 我亏了多少

```
你持有 120 股，今日 −$1,043，累计仍 +$2,180
```

纯算术，无任何主张。

**这一块与持仓列表重复，是有意的。** 口径不同 —— 持仓列表给的是这只票的总盈亏，
告警卡片给的是**这一次异动造成的变化**。告警是一次打断，
打断必须自带足够上下文让用户当场决定要不要行动，而不是让他再去翻另一页。

### ④ Allocation · 三个切面

**不做独立的「组合体检」侧栏。** PF2 / PF3 并入 Allocation 作为第三个切面，
与「按标的」「按资产类别」同一套条 + 同一套图例。

```
按标的       NVDA 20.0% · BTC 16.7% · …
按资产类别    美股 79.9% · 加密 16.7% · 现金 3.4%
按主题       AI 49.7%（NVDA · AAPL · NEWCO）· Autos 13.2%（TSLA）
            无主题数据 33.7%（BTC · 0700.HK）· 现金 3.4%
```

**改动的理由是它本来就是构成不是体检。** PF2 / PF3 的四个口径里只有波动一个同向，
提不出任何风险主张；剥掉主张之后剩下的就是「组合在主题上怎么分布」——
那与另两个切面是同一件事的第三种切法，不需要独立区块。

⚠️ **加密与港股进「无主题数据」一档，不隐藏也不算 0。**
`themeExposure` 仅覆盖美股，缺失读数与零读数在条形图上长得一样、含义相反。

⚠️ **三个切面只陈述构成，禁止写「因此风险更高」「更容易同涨同跌」「建议分散」。**
PF2 四个口径只有波动一个同向；PF3 的主题增量只有 1.34 倍（盘中）/ 1.13 倍（日线）且切半不复现，
真正的驱动是流动性不是主题。

⚠️ 若界面用 35% 分色，须写明它是**业界惯例值不是回测值**。

### ⑥ 今日相关新闻（底部常驻）

**这不是 EV6，也不共用 EV6 的阈值。**
EV6 是挂在告警卡片上、有统计证据的归因源；这一块是**展示类，无统计主张**，每天都显示。

⚠️ **不要与 EV6 共用阈值 —— 两者目的相反。**
归因门要精度(错挂一条等于对用户断言一件假事)；展示块要召回(它什么也不主张)。
共用的后果是非触发日覆盖率只有 16%，**84% 的日子这块是空的**。

```
措辞     「今日相关新闻」，不是「原因」
相关度    ≥ 0.80             不是 1.0
主题      不设门槛            事件类主题门是给归因用的，展示不需要
时间窗    当日全天            不是 ±120 分钟
排序      按发布时间倒序，取前 N
```

**0.80 这个切点是实测的**（三只标的的当日全量返回）：

```
阈值    AAPL  PLTR  NVDA   该档最低那条长什么样
1.00     13     6     2    Apple stock price falls: 3 reasons why AAPL shares are down
0.90     21    11     6    Apple, Stryker, Coinbase And Other Big Stocks Moving Lower
0.80     25    13    12    Nvidia Is Back on Top as Most Valuable Company After Apple Stumbles
0.75     26    14    12    Liontrust Investment Partners LLP Trims Holdings in VeriSign   ← 垃圾从这里开始
0.70     37    19    17    Form 4 Marten Transport Ltd For: 31 July
```

⚠️ **放宽这一块不花钱。** `market-news` 一次调用返回当日全量（实测 90 / 76 / 100 条），
筛选在客户端做。**我们本来就已经为这些条目付过费了,只是把它们丢掉了。**

⚠️ **`relevance_score` 是字符串**（`"1"` 与 `"1.000000"` 并存），必须 `parseFloat` 再比。
见 [signal-spec EV6](signal-spec.md)。

### ⑦·五 零告警时展示判断依据

⚠️ **冷启动那天，Tab 1 上唯一由信号产生的内容是「0 条告警」** —— 其余全是组合状态，
用户在券商 app 里已经知道。**没有告警的时候，这一页是持仓看板不是盯盘产品。**

但有东西第一天就有：建 playbook 时给每只标的拉了两年日线、算了 σ 和分位、定了阈值。
**那批数字正是「什么算异动」的答案。**

零告警时，告警区在「今天没有异动」之后接着展示：

```
今天没有异动
扫描 6 只持仓 · 187 条新闻 · 6 只都在各自的常态范围内

                      价格                         成交量
             今天       触发线   平时         今天       触发线      过去两年
NVDA      +0.84% ▊░░░░  ±3.3%   2.23%     1.1× ▊▊░░░   2.0×     14 日线 · 14 盘中
BTC       +0.31% ▊░░░░  ±2.7%   1.79%     0.9× ▊▊░░░   3.0×      6 日线 · 17 盘中

```

⚠️ **「今天」两列是这张表的主语。** 只给基线和触发线，这张表是把配置打印了一遍，
用户看不出引擎有没有真的跑。**加上当日读数，「我们在看、今天没到线」才成立**——
而且这两个数不用额外取数：M2 与 M3 是 PV1 每轮必算的量，
零告警恰恰意味着两条腿都算完了、至少一条没过线。字段见 `findings.json` 的 `scan`。

⚠️ **填充条只按 `今天 / 触发线` 取比例，不做颜色分档。**
「接近触发」不预示任何事 —— 判据测的是触发后 5 日的波动放大，
从没测过「差一点触发」。给它变色等于凭空多一个主张。

#### 触发了的那一行要有明确标记，不能只靠「两根条都是琥珀」

这张表要答两件事：**看了什么**（读数）与 **结论是什么**（触发没触发）。
两根条都填满是「两条腿都过线」的**证据**，不是结论本身 ——
让读者自己比两根条再自己得出结论，等于把最后一步推给他。

```
触发     行首挂与告警卡同一个 pill 字形，可点跳到那张卡
只过一条  不加标记 —— 这正是产品要表达的那件事，底部说明已经解释
```

⚠️ **标记从 `findings` 取，不要从两根条的状态反推。**
「两根条都琥珀」与「这条 finding 存在」是同一件事的两次计算，
反推出来的第二份迟早跟第一份分家。**`findings` 是唯一事实来源。**

⚠️ **标记跟着当前粒度走。** 一只标的可能盘中触发而日线没触发（反之亦然），
切到哪一档就显示哪一档的结论。

⚠️ **投递被关掉时读数照旧、标记照旧。** 「过了线」与「推没推」是两件事 ——
关掉投递不改变今天两条腿都过了这个事实。

⚠️ **盘中的量能读数要标时间。** RVOL 分子是当日累计成交量，分母是过去 90 日的
全日中位数，14:30 跑出来的 1.1× 系统性偏低。界面写「1.1× 截至 14:30」，
收盘后去掉后缀。**不折算** —— 折算要一条没验证过的盘中成交量曲线。

⚠️ **价格列显示涨跌幅不显示 z。** 引擎判的是稳健 z，但 ±3.3% 就是 1.5 × 2.23%，
和当日涨跌幅同单位、可直接比。z 留在方法页。

⚠️ **两条线都要过，缺一不可。** 不能只写「超过 ±3.8% 就会提醒你」——
BTC 出现过日线 z = 4.64（价格腿超阈值三倍）而 RVOL 1.88 < 3.0，
**PV1 静默**。只讲价格线会让用户以为漏报。

⚠️ **「过去两年响过 14 次」是新用户最该先知道的一件事** ——
它同时说明三件：规则真的在跑 · 它多久响一次 · 它历史上响在哪。

⚠️ **表的内容与下面四条约束是定的，位置是 skin 选项。**
两版：扫描表独立成块放告警左侧 · 常驻在告警区内部底部并给触发行加标记。
**本节的位置描述不作数，内容与约束不受 skin 影响。**

⚠️ **这不是用内容填空白。** 这些是这个产品的判断依据本身；
平时它藏在方法页里，零告警那天正好是展示它的时机。

字段见 [output-schema](output-schema.md) `baselines[sym].triggerLine` 与 `historicalTriggers`。

### ⑦ 静默日也要说话

```
今日扫描 12 只持仓 · 187 条新闻 · 无异动
```

**81% 的告警日没有材料、大多数日子没有告警 —— 静默不等于系统没工作。**
一行说明让用户知道扫过了。

## 五、Tab 2 · 标的详情与告警历史

### 定位：选一只票，看它的全部相关信息

顶部是持仓标的切换器（有 portfolio 则自动带出，否则用用户报的列表）。

**入口在持仓表** —— 点持仓表任意一行，切到本页并选中该标的。
顶部保留切换器，可以在不回 Tab 1 的情况下换标的。

| 模块 | 数据来源 | 状态 |
|---|---|---|
| **两年 K 线 + 信号历史** | 约 502 根日线 + 该标的历史触发 | ⭐ 本页主体 |
| 价格与幅度 | 现价 · 当日 · 5 日 · 距 52 周高低 + 52 周区间轴 | 描述性 |
| 覆盖状态 | **PV4** + `M23` 分布可用性 | 元信息 |
| 相关新闻 | 该标的近期稿件，不限触发日。**与首页 ⑥ 同端点同筛选链（宽链）**，只是范围不同 | 展示类 |
| 内部人申报 | **EV1** 簇买 | — 记录类 |
| 财报日历 | **EV4** 下次财报日 + 盘前/盘后 | — |
| 资金费率（仅加密） | **DR1** | 🟠 |

##### 内部人申报 · 卡头报人数，轴点带明细

**卡头第一个数字是人数,不是笔数。** EV1 的判据是 $\lvert\{\text{owner\_name}\}\rvert \ge 2$ ——
不同的人数。笔数单独看会误导：

```
NVDA   20 笔 / 2 人     二十笔看着很多，其实只有两个人
PLTR    2 笔 / 1 人     一个人，构不成簇
```

写成「9 天内 **3 人** 3 笔申报」。**人数与笔数相等时也照写**，
省掉之后读者无从知道哪个是判据。

```
轴点颜色   按交易方向，与「买入 / 卖出」徽章同色。⚠️ 不用蓝色，那是用户线专属
轴点大小   按该日笔数。⚠️ 不按股数 —— 那会做出一个我们不做的重要性判断
hover     日期 · 该日人数与笔数 · 方向 · 逐人姓名与股数
          ⚠️ hover 即出，不要点击；键盘 focus 同样出
          ⚠️ 日期是申报日不是成交日，tooltip 里要能看出来
```

**买入与卖出一起列。** 只列买入会让读者以为这只票没有内部人活动 ——
实测四只美股买入为 0、卖出 1–12 笔。

```
轴点     买入与卖出两种形状（或两种颜色），一眼可分
徽章     BUY / SELL 两色
不进告警流  两组都不进 —— Tab 2 是记录页，这里的东西本来就都不是明确信号
```

**判据是 `signalId` 在不在，不是 `code === "S"`** —— 后者是在页面上重做一次分类。

⚠️ 卖出没有 `signalId`：EV2 已移出已定案 13 条（🔴 已证伪，
且在大盘股上反向）。**这只决定它不进告警流，不影响它在这张卡上照常显示。**

⚠️ **没有买入时这一块照常出，不许消失。**

美股的 `insider` 键恒在（[output-schema §六·三](output-schema.md)），
`items` 为空是**空态**，不是缺省。整块不渲染只留给加密 —— 那才是真正的「不适用」。

```
有买入   照常
无买入   「窗口内 N 条内部人申报，没有一条是公开市场买入」
        并说明只有公开市场买入进这条信号
```

⚠️ **必须同时给 `filedInWindow` 和 `filings`。**
实测 AMD 窗口内 **100 条申报、买入 0 条**，NVDA 25 条、买入 0 条 ——
**只印「0 笔」会被读成「这只票没有内部人活动」，而事实是「有一百条活动，没有一条是买入」。**
这两句话对读者的意义完全不同。

⚠️ **块消失比空态更糟，因为它不留痕。** 空态说「查过了，没有」；
消失什么也不说，读者只能猜是没取到数据还是这只票不适用 ——
**而这两种猜测里没有一个是对的。**（原则六：沉默要有措辞）

##### 价格与幅度 · 两条渲染规则

**① 方向色只给「移动」，不给「距离」。**

```
上色    当日 · 近 5 日            它们是收益，符号会变，红绿在传达今天发生了什么
不上色  现价 · 距 52 周高 · 高于 52 周低
        ⚠️ 后两项的符号是结构性固定的 —— 永远 ≤ 0 和 ≥ 0。
          给它们上色会让一个恒定属性看起来像今天的消息
```

**② 区间轴三处都要标注,否则读者不知道它在画什么。**

```
左端   52 周低 103.90        右端   52 周高 174.57        圆点   现价 118.20
```

⚠️ **它与上面两行是同一事实的两种表示**（答案 vs 形状，同 PV4 覆盖卡的
`sizeRank` 与 `histogram`）。**允许并存，但轴必须自己说清是什么** ——
一条没有标注的横轴读者只能猜。

### 两列并排时，矮的那张要把内容补足，不要留行内空白

两列网格的行高等于较高那张，矮的那张下面会空出一块。**卡片本身已经贴着内容收边**
（实测底部余量统一 17px，那是内边距），空的是它旁边那半行。

**解法是把矮卡的内容补足,不是改布局。**

| 卡 | 现状 | 补什么 |
|---|---|---|
| 财报日历 | 只有「下次财报 + 盘前/盘后」一行 | **加历史财报日时间轴** —— `earnings.past[]` 契约里已经有 6–8 个，画法与内部人那条时间轴同一套 |
| 覆盖状态 | 两条进度条 + 一句说明 | 说明可展开：这只票的基线长度、分布可用性检验结论、不足时哪些信号停用 |
| 加密（Tab 3） | 恐惧贪婪 + BTC 市值 | 恐惧贪婪的近 30 天走势 —— 一个孤零零的数看不出它高不高 |

⚠️ **不要用瀑布流。** 它让矮卡下面直接接下一张，代价是列不再对齐、阅读顺序变成「先下后右」。
**只有在补足内容之后仍然差得多时才考虑。**

⚠️ **不要按高度配对。** 卡片高度随标的变 —— NVDA 内部人 3 笔 256px、SOUN 0 笔整块不显示。
固定配对必然在某些标的上失效。

### 图例每一层都要有 tooltip

**勾选框只给了名字,没给定义。** 「Intraday move」和「Price-volume move」在图上是两种颜色的点，
但它们判的是两个不同的量 —— 不解释,读者只会当成「一个粗一个细」。

**每层的 tooltip 说三件事:判什么 · 用什么做尺 · 不代表什么。**

| 层 | 判什么 | 尺 | 不代表什么 |
|---|---|---|---|
| **价量异动 · 日线** | 一整个交易日的价格偏离与成交量，**两条腿同一天都过线**才算 | 价格用这只票自己的稳健波动；成交量用它自己的中位数 | 不预测方向。触发之后涨跌各半 |
| **价量异动 · 盘中** | 单根 15 分钟 K，同样要两条腿都过 | **基线取过去 90 天「同一时刻」那根** —— 开盘和收盘本来就比午盘大 | 不是日线的缩小版。两者的线不可换算 |
| **你设的线** | 你自己定的止损 / 止盈 / 回撤被触及 | 没有我们的尺 —— 阈值全是你给的 | 不代表我们认为该行动 |
| **财报日** | 已排定的财报发布日 | 交易所日程，不是我们判的 | 不预测财报好坏，也不预测方向 |
| **费率极端**（仅加密） | 永续合约资金费率超出阈值的日子 | 8 小时原生粒度 | **不推送。** 它是区间状态不是事件；不得写「多头拥挤」「杠杆过高」 |

⚠️ **tooltip 里不要写具体阈值数字。** 阈值逐标的逐资产类别不同，
从 `baselines[sym].thresholds` 读并就地显示，或者干脆不显示 ——
写死一个数，换一只标的就是错的。

⚠️ **「费率极端」那层的 tooltip 必须说明它不推送。** 其余四层都会推手机，
只有它不会 —— 同一个图例里混着两种性质，不说清用户会以为都会响。

### 两年 K 线是本页的主体

**它让用户自己核我们的话。** 卡片说「近两年第 7 大跌幅」，这里摊开两年让他自己数；
卡片说「本月第 3 次」，图上三个点都在；卡片说「已过滤低量噪音」，
把 PV3 那层打开，被滤掉的日子全部可见。

**这是把可信度从「我们声称」变成「你可以查」。**

```
范围     有多少历史显示多少（约 502 根）。不给用户拉 —— 基线绑死在这个范围
标记     圆点 · 大小 = |z| · 不编码方向 · 三级用大小与填充区分
可过滤   PV1 · PV5 · PV3（被筛掉）· 你的线 · 财报日 ·（仅加密）DR1
图例     按实际画出的层级生成
```

⚠️ **不显示分位排名 —— 但理由不是「口径不同」。**
这里原来写着「『近两年第 7 大』是 60 根窗口口径下算的，放到两年图上会让人以为
那个排名是从这张图数出来的」。**这句话现在是错的**：分位排名取的是
`rets[-502:]`，与这张图**同一个范围**。60 是「基线最短可用门槛」（PV4），不是窗口，
两个数在早期实现里曾经是同一个，后来分开了而这句话没跟着改。

口径既然相同，这张图正是用来核那个数的地方 —— 这也正是上面「让用户自己核我们的话」
说的事。图上仍然不重复印这个数，理由只有一条：**它在卡片上已经有唯一去处**，
两处各印一遍就会各自漂移。

⚠️ **不搬 `mock/signal-browser.html` 的回测统计** —— 「中位 V 后 5 日波动」
「中位 |后 5 日收益|」「年化频率 F」一个都不要。那是研究工具的数，
给每个触发点配一个「后来涨跌了多少」，用户必然当胜率读，
而**判据只测波动放大**，它根本不是收益指标；且逐标的样本在 30 条以下不可信。

⚠️ 同理不要「当前筛选触发数」这类计数面板。那是调参界面，不是产品。

### 页面顶部一句总提示，逐条只放数据

**不要在每个模块下重复验证结论。** 那是研究语言，不是产品语言。

```
页面顶部（固定）
  本页汇总与你持仓相关的客观信息，仅在此处显示。
  数据的验证结论见「方法」页。
```

**逐条只显示事实**：

```
NVDA · 内部人申报
  8/11  NEWSTEAD JENNIFER   减持
  8/13  ...
```

⚠️ **验证结论只出现在两处**：本页顶部那一句（概括）· 方法页的「什么是噪音」（完整）。
逐模块重复会让页面变成一份研究报告。

⚠️ **给实现者的约束**（不是界面文案）：本页任何模块都不得出现方向性措辞 ——
不写「减持是利空」「机构看多」「建议关注」。只陈述发生了什么、什么时候。

## 六、Tab 3 · 市场

### 开头必须有一句

> **本页是客观市场数据。我们的判断在「方法」页，触发的信号在首页告警区。**

英文：`This page is objective market data. Our judgements are on the Method tab; the signals that fired are on the first tab.`

**纠正要写成指路，不要写成否定。** 这里要纠正的假设是真实存在的 ——
用户在一个信号产品里看到一屏市场数据，确实会默认它是信号源，
所以这句不能省（对比 Tab 2 的 `p2Standing`：那里否认的是没人做过的假设，是凭空树靶）。

但否定式把读者停在「那判断在哪」这个问题上。**指路同时做了两件事**：
说明这一页是什么，并把读者送到判断真正所在的地方。

⚠️ 这条是「不用否定式说明」这条写作约定的边界案例，**判法记在这里**：

```
假设是读者真会做的        →  必须纠正，但用指路或正面陈述
假设是文案自己树起来的     →  整句删掉
```

### 内容

**九个端点已逐个实测，全部可用**（2026-08-20）：

| 分区 | 端点 | 实测拿到什么 |
|---|---|---|
| 指数实时 | `macro/index/real-time` | `symbol · date · price` —— SPX 7641.16 · VIX 16.01 |
| 指数历史 | `macro/index/historical` | OHLCV + `change_percent` + VWAP |
| **利率** | `macro/treasury-rates` | **完整曲线 13 档**：1M / 2M / 3M / 6M / 1Y / 2Y / 3Y / 5Y / 7Y / 10Y / 20Y / 30Y |
| 商品 | `macro/commodity/symbols` + `real-time` | **40 个品种**，黄金 GCUSD 4590 |
| 加密情绪 | `crypto/fear-greed-index` | 日频，`timestamp · value · time` |
| 加密市值 | `crypto/market-cap` | BTC $1.33T，日频 |
| **日历** | `stocks/earnings-calendar` | **不传 symbol 即全市场**，带 `bmo` / `amc` |

#### 三个超出预期的可用性

```
美债给的是完整收益率曲线    可直接画期限结构，并算 2Y–10Y 利差（倒挂指标）
财报日历不传 symbol 即全市场  「今日/本周财报密集度」直接能做，不必逐只查
商品有 40 个品种            不只黄金原油
```

#### 两处实现要注意

```
时间戳不一致   SPX 20:04:57Z · 黄金 03:05:01Z（差 7 小时）
             商品 24 小时交易、美股不是。并排显示必须各标各的时间
恐惧贪婪的措辞  写「恐惧贪婪指数 31」，不写「市场处于恐惧」
             它是情绪指标，展示可以，不能据此下判断
```

### 按持仓的资产类别决定显示哪些块

**跟告警图例同一条规则** —— 只显示与用户实际持有的资产类别相关的块。
没有加密仓位的人不需要看恐惧贪婪指数,那是噪音不是背景。

```
指数 SPX·NDX·DJI·VIX     持有美股时显示
本周财报                  持有美股时显示
加密 恐惧贪婪·总市值·BTC 占比  持有加密时显示
国债曲线                  始终显示 —— 利率是两类共同的宏观输入
商品                     始终显示 —— 不属于任一资产类别
```

⚠️ **是隐藏整块,不是置灰。** 与图例那条一致：不适用 ≠ 暂时没有。

⚠️ **块少了要能看出是因为持仓,不是因为坏了。** 页面开头那句话里补一句
「本页按你持有的资产类别显示」，否则用户会以为数据没加载出来。

#### 加密块里的数字全是全市场，不是你的持仓

```
加密总市值 $3.02T   全市场
BTC 占比 44.0%      BTC 占全加密市值的比例
```

⚠️ **必须标出来。** 在一个持仓产品里，「加密」卡下面的「BTC 占比」

或者把卡名写成「加密市场」。用户自己的资产类别占比在 Tab 1 的 Allocation 里。

## 七、Tab 4 · 方法

作业明确交给 Skill 决定的三件事，答案要有一个用户能找到的地方。

### 什么算异动

```
定义        价格与量能同时越线（signal-spec PV1 / PV5）
两条腿      单看价格会把低量跳动算成异动；单看量能实测最弱
AND 而非 OR  等触发数下两者打平（p = 0.70–0.84）。选 AND 是选量：
            OR 是 AND 的 5.96 倍触发日，5 只组合 5.6 次/周 vs 1.0 次/周
⚠️ 依据封顶   按时间切半后六种口径全部符号翻转，这条决策的证据封在 🟡
```

### 什么是噪音 ⭐ 这一节是本产品最有说服力的部分

```
测了 21 条告警候选，通过判据的 4 行（PV1 股/币 · PV5 股/币）
判据只有一条：触发后 5 个交易日的波动，相对同波动率分层的净化基准，
             95% 区间下界 > 1.0 且独立块数 ≥ 5，逐标的算，禁止池化
```

分四类呈现，**每条给具体数字不写「无效」两个字**：

**21 条候选测下来，4 行通过** —— 价量异动的日线与盘中，各在美股和加密。

没通过的分四类，**因为「没通过」不是一件事**：

| 类 | 例 |
|---|---|
| 已证伪 | 内部人簇卖：56 只标的零通过，倍数中位 1.00 —— 与随机无异<br>发布预告：16 只零通过<br>宏观传导：切半符号翻转，留出样本 0/16 |
| 效应太小 | 分析师簇：中位 1.117，而价量异动是 1.49 —— 效应真实，单标的上不够用 |
| 数据阻断 | FOMC 决议：平台没有前瞻宏观日历端点，测不了 |
| 不可复用 | 费率极端：8 小时粒度 24/25 通过，但把触发日整体平移 ±30 天造出的伪触发也给 22–24/25 —— 它测的是区间状态不是事件。**所以它留在页面上，但从不推送** |

⚠️ **界面上只写名字，不写内部 ID。** 用户没听说过 `EV2`，「内部人簇卖」他看得懂 ——
ID 是我们的索引，不是他的信息。

⚠️ **四类不是装饰，它是「测得够细」的证据。**
尤其最后一类：费率极端在 8 小时粒度上 24/25 通过，**任何只跑一次的检验都会放它过** ——
是造了伪触发去比，才发现它测的是区间状态。一个只做过一轮检验的产品列不出这一类。

⚠️ **费率极端那条与其余五条性质不同** —— 它在已定案 13 条里，屏幕上看得到（Tab 2 加密标的）。
它回答的不是「一个没做的东西为什么没做」，而是**「一个你看得到的东西为什么不吵你」**。

### 多信号并发怎么排序

```
优先级 = 严重度 × 仓位权重 × 新颖度
```

- **严重度**只做排序输入，不再决定投递渠道（决策 #5 推翻配额层之后）
- **仓位权重**：同样一条 PV1，落在 40% 仓位和 3% 仓位上不是一回事
- **新颖度**：同 `anomalyEpisodeId` 的延续更新状态，不重复推送

**不设条数配额。** 一周里真的发生很多大事就该收到很多条 ——
用条数上限截断等于「市场越有事，越不告诉你」。实测截断量集中在爆发周。

⚠️ **横截面残差可以显著压低并发**（盘中：告警落在大盘大动 bar 美股 53.5% → 38.0%、
加密 79.9% → 53.6%；单根 bar > 50% 齐鸣 8 根 → 0 根；最忙 session 559 条 → 268 条）。
但该结论判据测不了、阈值样本内标定、且加密的运行时基准不可实现 —— **标 🟡，未采用**。

### 能力边界

| 边界 | 内容 |
|---|---|
| 判据只测波动放大 | 触发后是否比平时更动荡。不通过波动表现的信息测不到 |
| 归因只能说「当日同期」 | 判别力 79% 在日级、21% 在 bar 级，截断口径下 bar 级只在 11:30 ET 前成立 |
| 归因覆盖约 19% | 受 EV6 严过滤链限制（相关度 = 1.0 · 事件主题 ≥ 0.5 · ±120 分钟），其余落 `none` |
| 加密拿不到归因 | **不是端点不覆盖** —— `market-news` 能用加密符号查，但六口径相关度全 < 1.0（最高 0.9999），过不了 `= 1.0` 那道门。BTC 新闻饱和、其余 24 个近乎没有新闻 |
| 归因不可复算 | 七个文件里唯一一处 LLM 输出，同一条告警跑两次措辞不同。因此必须署名模型与生成时刻 |
| 用波动验波动共线 | 凡本身是波动预期的候选量（如隐含波动率）都与判据共线 |
| 输入只有三类 | 价量 · 事件 · 文本。期权 IV 与横截面残差已试过，见 results-topic-alt-inputs |
| 无前瞻宏观日历 | 平台端点缺失，FOMC / CPI 提醒做不了 |
| 新上市标的盯不准 | 基线不足 60 日，见 PV4 |
| 主题维度增量很小 | PF3 逐对口径下只有 1.13–1.34 倍且切半不复现，真正驱动是流动性 |
| 样本选择偏差 | 92 美股 + 25 加密，覆盖 11 个 GICS 部门，但不是全市场 |
