# Eval 方案

**这一份是唯一的 eval 方案。** 它合并了 `product/eval-plan.md`（冻结留档）与早先的
`eval/queries.md`（已删）。两份并存时案例集与打分口径互相矛盾，而 eval 的全部意义
就是给出一个可信的数 —— 方案本身有两个版本，那个数就没有意义。

---

## 一、这个 eval 要回答什么

作业的核心要求是**复用性**：对没见过的组合也能用。所以要回答的只有一句：

> 把这个包交给一个没参与过设计的 agent，它能不能建出一个**正确**的 Playbook。

「正确」拆成可判的东西 —— 见 §四 的五档判官。**不回答**「阈值定得对不对」，那是
`backtest/` 的事；eval 只判「有没有用对表里的数」。

---

## 二、闭环：真跑一遍，然后只验产物

```
一句话 query → 干净 session（只装官方 skills + dist/portfolio-watch）
                  ↓  agent 自己走完 SKILL.md 八步
            ~/playbooks/<name>/  ← 被测产物
                  ↓  拉回 eval/runs/<ts>/
            L0–L5 判官 → report.md · report.json
```

| 步 | 做什么 | 注意 |
|---|---|---|
| ① | `python3 skill/bundle.py` → `dist/portfolio-watch/` | 软链必须变真文件，否则 references 全是坏链接且断得很安静 |
| ② | 空目录起 session，装官方 skills + 我们的包 | 见下四条 |
| ③ | 投一句话，之后不说话 | 除非 Skill 自己按 1.4 提问 |
| ④ | agent 跑完八步 | 我们不介入、不提示、不纠正 |
| ⑤ | `alva fs readdir` + `read` 取回产物 | |
| ⑥ | 查平台副作用 | **四条 cronjob**（盘中 · 日线 · 盘前 · 市场）· feed · 订阅 |
| ⑦ | 判官逐层跑，几分钟后核 `credits items --today` | §八 |

### 干净 session 的四条

```
① cwd 必须是空目录，不能在本仓库里开
   —— 本仓库的 CLAUDE.md 会被自动加载，里面是全部阈值、决策与实测数字。
      在仓库里开 session，等于把答案连同题目一起发下去
② 只装两样   npx skills add https://github.com/alva-ai/skills
             cp -r dist/portfolio-watch <cwd>/.claude/skills/
③ 只投 query 那一句
④ 全程留 transcript —— 交互行为那一类断言只能从它判
```

⚠️ **写 spec 的 session 不能当 runner。** 它知道全部答案，跑出来的东西证明不了
SKILL.md 写全了没有。

## 三、两段：先调试，再计分

**边测边修是开发，不是评估。** 若每条 query 之后都改一次 skill，跑到最后一条时
它已经被前面几条调教过，「没见过的组合」这个前提就不成立了。

```
第一段 · 调试   案例 A–H，可见，随便改 skill。目的是挖 bad case
第二段 · 计分   5 条**第一段从没用过**的 query，冻结 skill，一个字不改
                这一段的通过率才是「复用性」的证据
```

**第二段的标的由脚本抽，不由人挑。** 形状此刻定死并提交，具体哪几只到运行当天才由
`draw.py` 用当日 UTC 日期做种子抽出来。**挑不了标的，就没法对着标的调 skill。**

| # | 形状 | 一句话模板 | 压什么 |
|---|---|---|---|
| S1 | 美股个股 × 3 | 盯下我的 {A}、{B}、{C}，有异动告诉我 | 基准路径能不能复现 |
| S2 | 加密 × 4 | 帮我盯 {A} {B} {C} {D} 这几个币 | 加密分支 · 少五条信号 · 无市场基准 |
| S3 | 美股 × 2 + 加密 × 2 | 我持有 {A} {B} {C} {D}，帮我监控 | 两套阈值并存 · 混合账本的 asOf |
| S4 | 美股个股 × 22 | 盯我这一篮子：{…} | 投递上限与排序真正起作用 |
| S5 | 美股 × 1 + ETF × 2 + 加密 × 1 | 盯 {A} {B} {C} {D}，跌破成本价提醒我 | 三类同现 · 未验证类别不得标 🟢 · 用户线 |

抽样规则（写死）：

```
池       backtest/universe/universe.csv —— 92 美股 + 25 加密
ETF      SPY · QQQ · IWM · TLT · GLD · XLE · XLF · XLK（池外固定候选）
种子      运行当日 UTC 日期 YYYYMMDD
不放回    同一条 query 内不重复
排除      第一段用过的全部标的
```

## 四、案例按输入形态切，不按信号切

Skill 的分支几乎全部由输入形态决定 —— 资产类别、有没有仓位、基线够不够、是不是第二轮。
按信号切会把同一条 PV1 在三种类别下的三种行为混成一个用例。

| 案例 | 一句话输入 | fixture | 覆盖的分支 |
|---|---|---|---|
| **A 混合有仓** | 盯下我的持仓，有大事提醒我 | `mock/data/`（真实取数） | 美股 + 加密 · `linked:true` · 日线与盘中同日 · 用户线 · 归因 |
| **B 其他类别 + 新上市** | 盯下我的 ETF 和几只新股 | `mock/data-outpool/` | `other` · `fallback_solved` · 基线不足停用 · 不启用 PV5 |
| **C 单标的无仓** | 盯一下 NVDA | 由 A 裁剪 | `linked:false` · 单标的 · 金额类整块不出 |
| **D 纯加密无仓** | 盯下 BTC、SOL、DOGE | 由 A 裁剪 | 仅加密 · 五条信号缺省 · 排名饱和 |
| **E 零告警日** | 同 B | 由 B 派生（`findings: []`） | 沉默措辞 · `scan[]` 是引擎跑过的唯一证据 |
| **F 跨轮增量** | 同 A，第二轮 | `state-<date>.json` 当上一轮 | 读-改-写 · 去重与冷却 · 裁剪 · θ 不重解 |
| **G 港股合成** | 盯下 0700.HK | 手工合成，标 `synthetic` | 只测措辞，不产出数值结论 |
| **H 交互探针** | 六条，见下 | 只有真跑才有 | 必须提问的三种 · 查不到的标的不静默丢 · 拒绝预测 |
| **I 读没读 reference** | 复用 A/B 产物 | — | **原则一有没有被执行** —— 四个 θ 只在 reference 里 |
| **J 初始化** ⭐ 新增 | 复用 A | — | 见下 |

⚠️ **C–F 必须由脚本生成，不许手改 JSON。** 手改的 fixture 与被测代码同时漂移时，
两边一致所以不报错。

⚠️ **港股拿不到真实数据**（`symbol=0700.HK` 返回 400）。「其他类别」的真实数据代表是
**ETF，不是港股**；G 案只验证界面在未知类别下不说错话。

### J · 初始化是一道独立的门

`scripts/init.js` 必须在任何 cronjob 之前跑，而页面缺任何一个文件都整页不渲染。
**这是最容易整条走空的一步**，且失败时 `feed.run` 吞异常、cronjob 报 `completed`。

```
J1  agent 有没有跑 init                        产物存在与否
J2  八个必需文件 + 每只一份 symbols/ 齐不齐      L0
J3  每只标的有没有 signalGrades                 没有 → 那只永远不推
J4  PV5 的档位跑在盘中 bar 上，不是日线上        days 字段的量级
J5  跑完之后 cronjob 是不是四条、cron 表达式对不对  盘前那条 UTC 小时必须 < 13
```

## 五、五档判官，能算的一律不交给模型

| 层 | 判什么 | 判官 | 挂了 |
|---|---|---|---|
| L0 结构 | 八个必需文件 + `symbols/` 在、schema 合法 | `check_schema_drift.py` | 该案 fail，后续层不跑 |
| L1 白名单 | `signalId ⊆ signals.json`（**13 条齐**）· 证据等级不越界 | 脚本 | fail |
| L2 参数 | 已验证类别阈值逐字等于 spec；`other` 是 `fallback_solved` 且可复算 | 脚本 + 复算 | fail |
| L2 账目 | 三条恒等式，容限 0.02 | 脚本 | fail |
| L3 自洽 | 覆盖 · 量纲 · 同源 · 归因四档 · 状态机 · 三道投递上限 | `eval/assertions.py` · `test_state.py` | fail |
| L4 渲染 | 零未捕获异常 · 无 NaN/undefined · 卡片有正文 · 页面数字对得上契约 | `eval/l4_render.js`（无头浏览器） | fail |
| L5 判断 | 需要判断的:有没有幻觉 · 相不相关 · 说得对不对 | 子 agent ×3，**三个角度** | 任一角度 fail = fail |

**三条通则：**

```
① 每条规则必须指向一个字段或一处渲染产物 —— 指不出来的写进 known-gap，不写进通过
② 同一事实只判一次
③ 数字白名单是代码层的硬门，不是 L5 的活 —— 模型判不了模型有没有编数
```

### 代码与 L5 的分界：读者自己发现得了吗

⚠️ **这条线在 2026-08-23 被重画过一次，理由值得留下。**

那天我给归因加了第二道代码门（可核来源为 0 就丢掉整段解释），一小时后撤掉：

```
写它的案例   BTC 卡说「coverage tied it to weekend-thin liquidity and
             Wintermute short positioning」，而唯一那条来源只讲「较历史高点低 41%」
门的判据     origin === "chain" 的条数 > 0
结果         那条**有** 1 条 chain 来源 → 门放行。**它拦不住写它的理由**
它真能拦的   来源全是模型自搜 —— 而页面每一行都标着「Alva 自行检索」、
             卡上印着「相关来源 · N 条」，读者本来就看得见
```

一道既解决不了目标案例、又重复了页面已有信息的门，只剩副作用：
**模型自搜是功能不是泄漏**，而它会把自搜出来的解释整段扔掉。

留下的判据只有一条 —— **读者自己发现得了吗**：

| | 读者能发现吗 | 归谁 |
|---|---|---|
| 编造的数字 | ❌ 卡上没有那个数，它来自读者看不到的页面 | **代码硬门** |
| 交易建议 · 方向预测 | 不是质量问题，是边界 | **提示词 + 禁用词表** |
| 解释里出现钟点 | ✅ 卡头就印着触发时刻 | 剥掉并留痕，不丢整段 |
| 来源全是自搜 | ✅ 页面标了「Alva 自行检索」 | 标注，不拦 |
| 语气 · 时序 · 相关性 | ✅ 读得出来 | 提示词，**判在 L5** |
| 说的和来源对不上 | ⚠️ 要点开链接读才知道 | **L5** —— 代码判不了语义 |

⚠️ **L5 判的是 eval 产物，不是线上实时输出。** 一条无源解释在生产里照样会推到用户手机上，
L5 只在事后测量里抓到它。这是已知且接受的局限 —— 要在运行时拦，就得再花一次
LLM 调用去判自己刚写的那句（每卡多 100–330 credits），不值。
缓解靠三样，都不是硬门：提示词 · 页面把来源摆在句子旁边 · 用 L5 的判决反过来改提示词。

### L5 的三个角度，以及为什么不用多数决

```
A  来源支撑    summary 里每个事实性说法，能不能在它自己的 sources 里找到出处
B  措辞越界    对着归因提示词那八条规则逐条撞 + 语言跟随 + 钟点时刻
C  与数据一致  数字对得上 measured 吗 · timing 字段按定义重算对吗
```

⚠️ **合票用全票制。** 三个判官判的不是同一个问题：

```
❌ 多数决   一条无源解释只要措辞干净、数字对得上，就 2:1 过了
✅ 全票制   角度不重叠，每一票都是独立否决权
```

多数决只在**同角度重复投票**时才成立。把三个角度当成对同一个问题的三次采样，
是把「角度」误当成「重复」。

⚠️ 判官是**主 session 的子 agent**，不是 Alva 的 `ask()` —— 后者一次 110–330 credits，
三票就是一千。子 agent 零 Alva 成本，而且能真正独立开三个：同一个上下文里问三遍不叫三票。

⚠️ **「重算」必须逐字照抄被测那一侧的算式。** 判官已经因此误报过两次
（BC14 把隐藏的卡数成空的卡 · BC25 拿「字段存不存在」当「时刻早不早」）。
凭印象重写一遍，写出来的是另一个函数，而它照样给得出一个看起来合理的答案。

### 真跑判不变量，回放判金标准

真跑的产物每天都不一样。**写死数值的规则拿到真跑上必然误报**，所以同一条约束写两遍。

| 约束 | 回放（金标准） | 真跑（不变量） |
|---|---|---|
| 未验证类别 | GLD 的 θv 恰为 1.75 | 凡 `other` → `fallback_solved` 且池级反解可复算 |
| 覆盖 | `scan[]` 恰好 8 只 | `scan[]` 集合**等于**持仓集合 |
| 账目 | `Σ + cash = 85317.0` | `Σ + cash = kpi.totalValue`，容限 0.02 |
| 量纲 | 加密盘中 z 为 18.63 | `\|z\| ≥` 该 (unit, 类别) 的 θz |
| 归因 | `summary` 逐字相同 | 数字白名单通过，`timing` 等于那个纯函数 |
| 投递 | SOL 的 PV5 为 L1 | 三道上限取最严，且 `cappedBy` 说得出是哪一道 |

> **一条规则如果翻译不成不变量，它就只是这份 fixture 的性质，不是 Skill 的性质。**

## 六、打分：硬门与记录分开，不给总分

```
L0–L4 任一条挂  → 该案例 fail，报「期望 vs 实际」两侧的值
L5              → 一致通过 · 三次分歧（转人工）· 明确越界（fail）
```

⚠️ **不给加权总分。** 案例平均分会让「账目差 0.03」和「编造数字」折算成同一个扣分。
**汇总不得把失败态折叠进正常态。**

**第二段报的是两个数,不是一个:**

```
通过案例数 / 5        —— 复用性的主张就是这个数
逐层失败清单          —— 挂在哪一层比挂了几条更有信息
```

`known-fail` 单列，每条三个字段：`断言 · 为什么现在挂 · 到期日`。
**没有到期日的预期失败会变成背景噪音**，三周后没人再看那一行。

## 七、每条断言先被弄挂过一次才算数

**一个不可能失败的断言等于没有断言。** 每条规则配一个变异，变异后必须报警。

| 变异（只改被测那一侧） | 应当报警 |
|---|---|
| GLD 的 `thresholds.source` 改成 `validated` | L2 参数 |
| `scan[]` 删掉一只 | L3 覆盖 |
| finding 的 `symbol` 改成不在持仓的票 | L3 覆盖 |
| `summary` 里塞 `09:45 ET` | L3 归因 |
| 加密盘中 `measured.z` 从 18.63 降到 6.0 | L3 量纲（θz = 10.0） |
| `cash` 加 1.0 | L2 账目（容限 0.02） |
| `signals.json` 删掉 PV1 | L1 白名单 |
| `summary` 里塞输入里没有的数字 | 数字白名单硬门 |
| 某只标的删掉 `signalGrades` | 三道上限 —— 应封 L2 而不是放行 |
| 用户线的 `unit` 改成 `session` | L3 量纲（`line` 只归 US 族） |
| 日线与盘中的 PV 合并成一张卡 | 共现合并键含 `unit` |

**变异只改一侧，不能两侧同改** —— 两边一致就不会报错。
**变异幅度必须大于断言阈值**：账目容限 0.02，就不能用 0.01 去试。

## 八、成本：回放零 credits，真跑先估再跑

```
回放   全部走录制 fixture，一次调用都不发                0 credits
真跑   取数大多免费（日线 · 盘中 · 日历 · 内部人 · 费率 · 宏观）
       归因 ask()      ⚠️ 实测约 208 credits/次，不是 21
       market-news     1 credit/次
       内部人           1 credit/次
       MCP 工具调用     计费为 ask()
```

⚠️ **归因单价此前记的是 21,错了一个数量级。** 一次逻辑调用在账单里是 5–8 条：
一条 79–279 的 rollup 加若干条 1–5 的检索条目。拿条目数除总额得到的均价不对应任何东西。
**按 `createdAtMs` 排序、认出 rollup、数 rollup 的个数。**

**一次真跑的量级由「这一轮几张卡调了模型」决定。** `attribution.dailyCap` 默认 10 →
单次上限约 2,080 credits，占每日额度三分之二。**跑之前把 cap 调到 1–2。**

```
真跑   每周一轮，且每次先估
回放   随时跑
L5 判官  卡数 × 3 × 约 208，默认关
```

⚠️ **成本按端点核对，不看余额** —— 计费有分钟级延迟，即时读余额看到「没变」是假的。

## 九、造判官的顺序

| 批次 | 内容 | 为什么是这个顺序 |
|---|---|---|
| 第一批 | A · B 回放 + L0–L3 + §七 变异表全跑通 | **判官必须先在已知答案的产物上被弄挂过**，才有资格判未知产物 |

| `check_skill_refs.py` | 包内引用有效 |
| `test_state.py` | F 案状态机回放 |
| `backtest/scripts/smoke/run.js` | 四个 producer 在桩环境里真的跑一遍 |

## 十、这个 eval 测不到什么

**必须原样写进一页纸。**

```
阈值本身对不对      判据与回测在 backtest/，eval 只判「用没用对表里的数」
回放测不到端点变更    fixture 是冻结的，端点改了只有真跑会发现
真跑测不到稳定性      行情与模型每次都不同，可复现性只能在
                   「同一天同一 query 连跑两次」这个窄口子上判
判官的判官          L5 三次一致只说明稳定，不说明正确
组合层行为          阈值在单标的上验证过，组合级属第二阶段
港股与 A 股         无真实数据，只覆盖措辞
真实券商账户         映射层写了，但需要一个「多笔 + 含空头 + 非单一币种」的账户才能真验
真实推送到 IM        属发布后的手工验收
```
