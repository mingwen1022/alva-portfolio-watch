# L · 触发演练：把从没响过的信号逼到真响

十七轮真跑之后，能推手机的五条信号里**只有两条产出过 finding**：

| | 产出过 | |
|---|---|---|
| PV1 | **0 条** | 唯一通过回测判据的信号 |
| PV5 | 7 条 | |
| US1 止损 | **0 条** | 线设了，价格没到 |
| US2 止盈 | **0 条** | 同上 |
| US3 回撤 | 2 条 | |

⚠️ **[[BC56]] 就藏在 PV1 那条没走过的分支里** —— 一旦真响，`move is not defined`
把整个日线 producer 打挂，`scan` / `portfolio` / `series` / `meta` 全都不写，
**PV1 触发的那一天页面反而是空的**。它躲过十七轮，只因为没有一只标的真的越线。

这个案例的唯一目的是**让它们真的响一次**，然后看完整链路：
触发 → finding → 投递分级 → 推手机 → 归因。

## 四只标的各自的差事

| 标的 | 为什么 | 当时价格 |
|---|---|---|
| **NVDA** 止损线 230 | 现价 **低于**线 → US1 第一轮就触发 | 214.72 |
| **SOFI** 止盈线 15 | 现价 **高于**线 → US2 第一轮就触发 | 18.91 |
| **ANAB** | 2026-08-24 盘前发财报 → EV4 的 `days <= 1` 成立 | 57.74 |
| **BTC** | 加密把 `findings.asOf` 顶到 08-23；纯美股账本停在 08-21，EV4 就差三天不响 | 77075 |

⚠️ **线是「已经越过」的，这不是造假 —— 用户新设一条已被穿过的止损是常事。**
要测的是「响没响」，不是「什么时候响」。

## PV1 不在这个案例里

真实数据下 PV1 当天不可能保证触发，θ 也不能为了测试改。
它走另一条路：**把 θ 临时压到必触发 → 验完整链路 → 还原**，
脚本在 `eval/pv1_drill.py`。这是唯一能走到那条分支的办法。
