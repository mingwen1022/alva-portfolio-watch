# 归因调用 · 实验记录

⚠️ **本文是实验记录,不是规格。** 已定案的调用配置在
[`../product/data-pipeline.md`](../product/data-pipeline.md) §九,那里只留跑通要用的东西。
**同一件事不在两处定义** —— 这里写「测了什么、结论是什么」,那里写「怎么调」。

归因的定位：**它给的是一段可能的解释,不是一个断言。** 底层等价于用户自己去网页搜一次,
只是我们替他把材料筛好、把话写好。**因此本文的测量目的是「跑不跑得通」,不是「准不准」。**

---

### 首轮实测 · 2026-08-21

样本取真实的 PV1 触发日：**AAPL 2026-07-31**，收益 −7.35% · z −5.56 · 量比 3.11 ·
502 根里第 2 大跌幅 · 同日 SPY +0.72%。材料由 EV6 严链在当日 80 条候选里选出 2 条
（14:36 与 14:39 ET，均为 Cook 谈内存短缺）。**三次调用,三条结论。**

#### `relevance_score` 是字符串，不是数字

```
AAPL  "1"          PLTR  "1"        NVDA  "1.000000"     ← 同一字段三种写法
```

**第一版过滤链用 `=== 1.0` 比,三只全部返回 0 条**,而实际有 13 / 6 / 2 条达标。
JS 里 `"1" === 1` 与 `"1.000000" === 1` 都是 false,**不报错,只是静默全空**。
必须 `parseFloat` 后再比。[signal-spec EV6](signal-spec.md) 的字段表已补类型。

⚠️ **这一条正是「零成本自洽检验」该抓的**：过滤链第一道门就归零,
而肉眼能在原始返回里看到 `rel=1` —— 不需要任何统计就能发现。

#### `opts.system` 是追加，不是替换

SDK 原文：「System prompt appended to the agent's default system prompt」。
**平台默认人格仍然在,而且在格式与语气上压过我们追加的部分。**

```
第一版   完全不输出 JSON，返回带 markdown 链接的三段散文 + 一句免责声明
        语言指令（写中文）也被忽略，返回英文
第二版   把输出契约挪到 user 消息末尾并加「首字符必须是 {」
        → 中英两版都吐出了 JSON ✅
        → 但 state 与 sourceIds 两个字段直接缺席，只有 explanation
        → 2–3 句写成 5 句；「显著」「unusually」「exceptional」全部出现
        → 中文版自带「后续应观察…」「不构成投资建议」
```

**结论：措辞黑名单不能只写在 system 里。** 长度上限、字段齐全、禁用词
三样都要在 user 末尾复述一遍。第三版照此改后,**同一输入连跑三次全部合规**：

```
合法 JSON            3/3      首字符 { 末字符 }
三个键齐全            3/3      state · explanation · sourceIds
state                3/3 linked，sourceIds 3/3 [0,1]      ← 稳定性首测同向
禁用词               0        显著·大幅·极端·预计·将会·建议·不构成投资建议 全未出现
长度                 58 / 68 / 58 字，上限 140
数字                 全部在输入集合内
```

⚠️ **三次不等于②层通过。** 判据是 5 次里众数 ≥ 4/5,这里只跑了 3 次,
且都是同一个样本。**记作「首测同向」,不记作通过。**

⚠️ **不要据此认为校验层可以省。** 前两版把三条格式约束全违反了,
差别只在提示词写法 —— 提示词能做对不等于每次都做对。① 层照做。

#### 数字白名单要按规范化后的形式比

复核第三版时我的校验脚本把 `7.35` 报成「越界」—— **输入里是 `-7.35`,
白名单存了带号的字符串,模型写的是不带号的。是校验脚本错,不是模型错。**

```
比之前先规范化   去正负号 · 去千分位逗号 · 去尾随零 · 百分号与倍号剥掉
                -7.35 → 7.35     3.11x → 3.11     1,250 → 1250
```

不做这一步,① 层会稳定地误拦正确输出,而误拦看起来跟模型不听话一模一样。

⚠️ **不要据此把 `model` 换成更强的模型。** 失败的是格式与语气约束,
不是判断力 —— 两次都正确识别出材料指向本标的、时点在前。
换模型解决不了追加式 system 的结构问题,只会抬成本。

#### 模型能检索，但指令必须是祈使句且写在 user 末尾

2026-08-21 实测。`ask()` 的沙箱里**确实有检索工具**,模型自报:

```
functions.exec · exec_command · alva run · getSerperSearch · searchBrave
```

**两次尝试,差别只在指令怎么写:**

```
写法                                              结果
system 里 "You may search... Only do it when      searchAttempted = false
the given material is not enough."                两个样本都没搜，其中一个
（5 句里 4 句是限制或劝阻）                          明写了「所给材料无法据此归因」
                                                 —— 它认出来了，但没有行动

user 末尾 "STEP 1 - SEARCH NOW. Do it before      searchAttempted = true
writing anything. Run a search for what moved     searchWorked   = true
AAPL on 2026-07-31."                             3 条来源，全部真实
```

⚠️ **「它能准确描述状况」与「它会因此改变行为」是两件事。** 本项目两次撞上：
陷阱题里它写「报道晚于收盘 127 分钟」然后照样判 `linked`;
这里它写「无法据此归因」然后什么也不做。**说和做之间没有连接,得用祈使句接上。**

**成本与耗时**（n=1,不外推）：

```
不检索    约 82 credits    11–14 秒
检索      288 credits      59 秒          约 3.5 倍，慢 4–5 倍
```

**找回来的东西质量高于 EV6 严链选出的材料** —— 三条全部指向真正的原因
（九月季营收指引偏弱 + 供应受限），而严链那两条只讲到内存短缺。

#### 「必须有可解析 URL」这条规格不能用 HTTP 状态码校验

模型给的三条 URL,直接 GET 全部返回 **401 / 403** —— Reuters 与 Bloomberg 对
非浏览器一律如此,**真路径与假路径的返回码一样**。用状态码校验会把真来源全部误杀。

可行的校验是**反查标题**：拿标题当精确短语查 `serper-search`（1 credit），
看返回里有没有同一条 URL。实测两条标题都命中,Reuters 路径逐字一致。

```
❌ HTTP 200 检查        付费墙站点全军覆没
✅ 标题反查             1 credit/条，能确认这篇稿子存在
⚠️ 都不能确认「发布时刻」  所以模型自找的来源不参与 timing 计算
```

#### 措辞黑名单挡不住换个说法

同一次调用里模型写了「**本文只作信息用途,不是投资意见**」——
黑名单里有 `仅供` `参考` `不构成`,一个都没命中。
**词表只挡已知的词。** 免责声明要按句式检测（结尾出现「不是/非…意见/建议」类整句），
或者干脆截断:解释超过 N 句就丢掉末句。

#### 补覆盖的第一顺位是财报日历，不是网页检索

`market-news` 之外的候选全探过一遍（2026-08-21）。**结论是别往网页检索方向找。**

```
来源                        单价      时间字段            能不能进 publishedBefore
earnings-calendar          免费    date + time（amc/bmo）  ✅ 交易所日程，无歧义
serper-search  type=news    1     date = observedAt        ❌ 索引时刻
search-brave               5     date = observedAt        ❌ 索引时刻，且与 age 自相矛盾
search-grok-x              ?     只回 AI summary，data 空   ❌ 那是判断不是材料
search-perplexity-finance   5     date = observedAt        ❌ 且本次直接拒答
```

⚠️ **`date = observedAt` 是这套 SDK 的家族约定,不是某个模块的 bug。**
`scrape-url` 的文档把 `date` 直接写成「Observation timestamp」。
**所以没有任何一个网页检索模块能给时序判据提供输入** —— 而时序判据正是上文
陷阱样本唯一被挡住的那一项。这是结构性的,换 query 不会变。

其余两条一次性观察（n=1,不外推）：brave 返回的首条是 Yahoo 行情页而非稿件;
perplexity 回「July 31, 2026 is still in the future」并且 `finance_search_invocations` 为 0。

**财报日历的覆盖增益已实测**（8 只美股 · 2025-01 起 · 端点覆盖起点）：

```
标的    财报次数  PV1 触发  落在财报窗  占比        窗口定义
AAPL       7      18       3      17%      time=amc → 次一交易日
NVDA       7       8       3      38%      time=bmo → 当日
MSFT       7      17       5      29%
AMD        7      20       4      20%
PLTR       7      14       3      21%
KO         7       7       2      29%
TSLA       7       5       1      20%
MSTR       8      13       1       8%
合计             102      22      21.6%
```

**21.6% 与 EV6 的 19.01% 同量级,而且两者大概率不重叠** ——
EV6 截断后的窗口是 14:00–16:00 ET,盘后财报按定义在 16:00 之后,
落不进那个窗。⚠️ **重叠率没有实测**（逐触发日取新闻要 102 credits）,
上面这句是从窗口位置推的,不是量出来的。

#### EV6 严链在收盘告警上结构性地漏财报

PV1 的告警时刻是收盘 16:00 ET,±120 分钟窗口截断后只剩 **14:00–16:00 ET**。

```
AAPL 2026-07-31   候选 80 → rel=1.0 13 → 事件主题 13 → 早于告警 12 → ±120 分 2
PLTR 2026-08-04   候选 66 → rel=1.0  6 → 事件主题  5 → 早于告警  5 → ±120 分 0
NVDA 2026-02-26   候选 90 → rel=1.0  2 → 事件主题  2 → 早于告警  2 → ±120 分 0
```

**三只里两只归零,卡在最后一道门。** 财报稿密集出现在盘后(20:30 UTC 之后)
与盘前,正好落在这两小时之外。19.01% 的覆盖率不是随机稀疏,**是窗口位置造成的**。

⚠️ **这不改变 EV6 的定案参数。** ±120 分钟是回测里唯一逐标的成立的一档,
换窗口要重测误挂率(spec 已记为独立验证项)。
这里记的是**为什么覆盖低**,不是提议改它。
PV5 的告警时刻在盘中,窗口位置不同,这个结构性问题对 PV5 不成立。

## 曾经的三层测试方案（已收窄）

⚠️ **下面这套是按「归因要出一个可信结论」设计的。**
2026-08-21 归因的定位改成「一段可能的解释,等价于用户自己去搜一次」之后,
②稳定性 与 ③判断质量 两层降为观测,不设通过线;`state` 徽章删除后 ②层已无对象。
**保留原文只为记录当时为什么那么设计。**

### 输出解析

平台 `ask()` **不支持结构化输出约束**（回测时用的 codex 支持，`ask()` 不支持），
所以只能从文本里解析。我们唯一一次真实跑过 LLM 抽取（10,757 条候选）留下三条：

```
① 输出会被包装        实测 9/9 批全部裹在 ```json 里，直接 parse 必失败
                     先剥包装再解析，不要指望模型听「只输出 JSON」
② 三种结局分开记录     成功 · 解析失败 · 规则拦截
                     混在一个「失败」计数里，就分不清是模型不行还是解析不行
③ 判据分可机检与不可机检  别把两类混进同一个通过率
                     我们曾把四条判据当成一体统计，其中一条根本没法机检
```

⚠️ **这三条不依赖 PO 族存在。** 完整实验记录见
[`../backtest/results-po.md`](../backtest/results-po.md) 附录，
但本节的实现不需要读它。

### 三层测试

依据来自本节自测：**同一份任务的三版提示词，输出合规性从「完全不合规」跳到「三次全合规」，
差别只在格式契约写在 system 还是 user 末尾。** 模型对提示词写法极敏感 ——
在一个样本上做对，不能推断在另一类样本上也做对。

⚠️ **判断层的稳定性我们还没测过。** 已测的三次是同一个正样本，`state` 三次都是 `linked`，
但正样本本来就不该翻。会翻的是边界模糊的那些（材料属同行 · 材料发布在移动之后），
**② 层就是去测这个,不要拿正样本的 3/3 代替它。**

| 层 | 测什么 | 判据 | 在生产里也跑 |
|---|---|---|---|
| **① 约束** | 数字白名单 · `linked` 必须引用 sourceId · 措辞黑名单 · 长度 · 语言 · state 合法 | 二值，任一不过即降级 | ✅ 这层就是校验层 |
| **② 稳定性** | 同一输入跑 5 次 | state 的众数占比 ≥ 4/5。**措辞不同不算失败，state 翻转算** | ❌ 仅测试 |
| **③ 判断质量** | 正 / 负 / 陷阱 / 边界样本 | 人工评分 | ❌ 仅测试 |

**③ 的样本构成**：

```
正样本   材料确实解释了移动（财报 · 明确公司公告）      应判 linked
负样本   材料是同行 / 行业的，与该标的无直接关系        应判 unlinked
陷阱     材料发布在移动之后                          过滤链就该拦掉，测的是拦没拦住
边界     加密（无大盘基准）· 未验证类别 · 三条材料互相矛盾
        盘中 bar（分位分母是同时刻的 90 根，不是 502 根日线）
```

⚠️ **样本必须来自真实数据。** 挑真实的 PV1 触发日、拉那天的新闻 ——
**造样本等于拿我们自己的想象去测提示词**。

⚠️ **成本不可预估。** `ask()` 按 token 计费，而测试正是要比较
「只传标题」与「传标题 + 摘要」两版 —— **两版的 token 成本差本身就是测试结果之一**。
先单跑一例、等几分钟查 `alva credits items --today`，再决定样本量。

#### 两条材料链的截断规则不同，这是 `after` 档能存在的原因

```
严链 EV6      相关度 = 1.0 ∧ 事件主题 ∧ |Δt| ≤ 120 分 ∧ **发布早于告警**
              ⚠️ 截断是它 🟡 证据的一部分（覆盖 19.01% 是截断口径；不截断是 25.73%）
              动它就等于换了一条规则，回测结论作废
宽链          相关度 ≥ 0.80 · 无主题门 · 当日全天 · **不截断**
              展示块用的就是它，归因材料的第二档也是它
模型自搜       无截断，发布时刻不可信（见下）
```

⚠️ **所以 `after` 永远不会来自严链,只会来自宽链或模型自搜。**
界面上解释筛选逻辑的文案**必须说清在讲哪一条链** ——
只写一句「±120 分钟」或只写一句「事后一律排除」，都会跟另一条链矛盾。

⚠️ **移动时刻的定义**（2026-08-21 补，原先只写「与移动时刻比较」，没定义）：

```
日线信号   当日 |z| 最大的那根 15 分钟 bar 的起点
盘中信号   触发那根 bar 本身
```

**不能用触发时刻。** 日线规则在收盘确认，用 16:05 去比会让全天所有稿件都算「事前」，
三档就没有内容了。⚠️ 这是个启发式：日线的「移动」本来就不是一个时点，
取最大那根是近似。**加密无收盘概念，取法相同（|z| 最大的 bar），但没有 RTH 边界。**

#### 模型能检索，但指令必须是祈使句且写在 user 末尾

## 归因解释里的时刻错，根因在我们拼上下文的那段，不在模型

2026-08-22。SOL 的盘中告警上下文里写着 `at: "09:00 ET"`，模型在解释里写
「未找到能直接对应 09:00 ET 该根下跌 K 线的单一新闻」——
而那根 bar 的实际东部时间是 05:00。**同一张卡上两个时刻。**

| | 上下文里给的 | 模型写出 | 卡头显示 |
|---|---|---|---|
| SOL PV5 | `09:00 ET` | 「09:00 ET」 | 05:00 ET |

⚠️ **初判「模型不换算时区」已撤回。** 模型逐字照抄了给定的串，行为完全正确 ——
**是我们把 UTC 的槽位号贴上 ET 标签递给它的。**

### 同一个错在两个互不相干的地方各犯了一次

```
界面的 clock()        切时间串 11..16 再拼 " ET"      新闻列表 12 条 + 盘中卡 3 张
拼归因上下文那段      取 barSlot 再拼 " ET"           SOL PV5
```

**两处都是「拿 HH:MM 拼时区名」。** 一个错能独立发生两次，说明拦它的位置不对 ——
不是提醒人别犯，是不让 `HH:MM` 这种半成品串流到显示层。
**槽位串是 UTC，是连接键，不是显示值。**

### 两道防线，缺一不可

```
上游   凡是要给人看的时刻（含递给模型的）走同一个 ET 格式化函数，输入是带偏移量的 ISO
下游   输出契约写死 Do not write clock times —— 卡头已经显示了触发时刻，
       解释里重复一遍，而那一份不受任何时区转换保护
```

⚠️ **「summary 里的时刻必须能在输入上下文里找到」这条断言挡不住它** ——
`09:00 ET` 确实逐字出现在输入里，**断言会通过而结果是错的**。
这是「核对的量与以为在核对的量不是一个」的又一例。已改为「不得出现时刻」。

⚠️ **现有 mock 数据里那条不重跑**，留作 eval 的已知失败样本
（`meta.gaps` 的 `attribution_time_zone_leak`）。重跑约 300 credits，
换来的只是一条正确的 demo 文案，不产生新知识。

### 加密的严链缺口同时被记进 meta.gaps

`crypto_attribution_unavailable` 已作废 —— 加密现在有归因，只是来源全部是模型自搜
（`origin: "model"`）。替换成两条更准的：

```
attribution_time_zone_leak      上面这条
attribution_no_chain_sample     严链只覆盖美股，当日 8 条告警的 PV 全在加密，
                                chain 那条渲染路径零真实样本。不造假数据测它
```
